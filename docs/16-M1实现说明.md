## 3. 关键实现

### 3.1 注册与验证

- 状态机：`pending_email → active`、`pending_review → active`、`active → banned/rejected`。
- 默认开启邮箱验证；关闭验证后注册即 active。
- 审核模式下即使验证邮箱，仍需管理员通过。
- 验证与重置令牌只存 SHA-256 哈希；原始令牌只出现在邮件链接。
- 开发模式（`GF_ENV=development`）注册页直接显示验证链接，便于本地联调。
- 登录时校验邮箱验证状态，避免“审核通过但邮箱未验证”的绕过。

### 3.2 主题与回复

- 楼层号使用 `UPDATE ... WHERE post_count = ?` CAS 分配，冲突时重试 3 次，保证主题内唯一。
- 首楼与主题在同一事务创建；分类/标签计数同事务更新。
- Markdown 使用 goldmark + bluemonday：原始 HTML 不输出，危险协议与外链属性被清洗。
- 编辑保留 `post_revisions`，作者受编辑时限约束，版主不受限。
- 私有/待审主题：列表不出现；详情仅作者与版主可见。
- 阅读状态使用 Upsert + `CASE WHEN` 只增不减。

### 3.3 媒体

- 限制：单文件默认 20MB（可配置）；仅 JPG/PNG/GIF/WebP。
- 双重校验：`DetectContentType` + `image.DecodeConfig`。
- 存储键：`{yyyy}/{mm}/{ulid}.{ext}`，通过 `/uploads/...` 提供访问。
- 编辑器上传后自动插入 `![](url)`。

### 3.4 通知

- community 在回复后发布 `post.created` 事件。
- notification 订阅事件，仅通知主题作者，跳过自己回复自己。
- `(event_id, user_id)` 唯一索引保证事件重放不重复。
- 头部铃铛显示未读数；通知页支持全部/单条已读。

### 3.5 后台

- 主题：置顶、精华、锁定、删除、恢复；筛选状态/板块/标题。
- 回复：隐藏、删除、恢复。
- 板块/标签：创建、编辑（板块）、删除（有内容时拒绝）。
- 用户：通过、拒绝、封禁、启用。

## 4. 与设计的差异

| 设计 | M1 现状 | 计划 |
|---|---|---|
| 用户组 + 信任等级 | 所有 active 用户获得默认发帖权限 | M3 用户组与 TL 门槛 |
| 邀请注册 | 返回“M4 开放” | M4 |
| 草稿/投票/慢速模式 | 未实现 | M1 余量/M2 |
| 全文搜索三方言 | 标题/摘要 LIKE | M2 |
| 图片缩略图/AVIF | 原图存储 | M2 |
| SSE 实时通知 | 服务端渲染未读数 | M2 |
| 迁移 | AutoMigrate | M1 后续切 goose |
| 权限缓存 | 每请求加载 | M3 |

## 7. M2 入口

1. **互动**：点赞、收藏、关注（主题/板块/标签/用户）。
2. **通知增强**：@提及、通知偏好、SSE 实时推送、轮询降级。
3. **私信**：会话、消息、已读、屏蔽、举报。
4. **搜索**：SQLite FTS5 / MySQL FULLTEXT / PostgreSQL tsvector，热词与建议。
5. **媒体**：缩略图、配额、孤儿清理、对象存储适配。
6. **补 M1 余量**：草稿、投票、慢速模式、用户设置页扩展。
