# 08 后台管理面板设计

## 1. 设计目标

1. **一个外壳，多模块贡献**：后台不写死业务页面，各模块声明菜单、页面、仪表盘卡片与设置组。
2. **一致的操作范式**：列表、筛选、批量、详情抽屉、审计在所有页面一致。
3. **权限可见**：无权限的菜单不出现；直接访问返回 403 并记录。
4. **危险操作可追溯**：删除、封禁、退款、改配置必须填写原因并写审计。
5. **与前台同一套技术**：Gin 模板 + Alpine + Pines + Tailwind，不做独立 SPA。

## 2. 外壳布局

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：Logo/站点名 │ 面包屑 │ 命令面板(Ctrl+K) │ 通知 │ 账号 │
├──────────────┬───────────────────────────────────────────────┤
│ 左侧导航      │ 内容区                                        │
│ 概览          │  页面标题 + 操作按钮                          │
│ 内容          │  筛选栏（可保存视图）                          │
│ 用户          │  表格 / 表单 / 仪表盘                          │
│ 审核          │  分页 / 批量条                                 │
│ 运营          │                                               │
│ 商业化        │                                               │
│ 站点          │                                               │
│ 系统          │                                               │
└──────────────┴───────────────────────────────────────────────┘
```

- 导航按模块贡献分组，组内按 `order` 排序；当前项高亮。
- 移动端（<lg）导航收进 Pines Slide-over；表格横向滚动或卡片化。
- 顶栏固定；内容区最大宽度 1440px；高密度表格行高 40px。
- 暗色与前台共用 token；后台默认紧凑密度。

## 3. 模块贡献机制

```go
package admin

type Contribution struct {
    Nav      []NavItem
    Pages    []Page
    Widgets  []Widget
    Settings []SettingGroup
}

type NavItem struct {
    Group      string      // overview/content/users/moderation/ops/billing/site/system
    Label      string
    Icon       string
    URL        string
    Permission string
    Order      int
}

type Page struct {
    Method     string
    Path       string
    Permission string
    Breadcrumb []string
    Handler    gin.HandlerFunc
}

type Widget struct {
    Key        string
    Title      string
    Permission string
    Size       string      // sm/md/lg
    Order      int
    Load       func(ctx context.Context) (WidgetData, error)
}
```

启动时：

1. 收集所有模块 `Admin()`。
2. 校验菜单/页面权限键已注册。
3. 按 `group, order` 排序。
4. 按当前用户权限过滤导航。
5. 仪表盘卡片各自超时（2s）加载，失败只影响该卡片。

新增模块只需实现 `Admin()`，后台导航、权限树、仪表盘自动出现，不改 `admin` 模块代码。

## 4. 统一页面范式

每个后台页面必须包含以下 **九要素**：

| 要素 | 要求 |
|---|---|
| URL 与权限 | 路径稳定；权限键明确；无权限 403 + 审计 |
| 页面标题 | 标题 + 一句话说明 + 主操作按钮 |
| 筛选栏 | 全部筛选写入 query string，可分享/刷新保留；提供“重置” |
| 保存视图 | 用户可保存筛选组合为视图（个人/全局） |
| 表格 | 列可配置；支持排序；空列有占位；数字右对齐；状态用徽章 |
| 行操作 | 主要操作外露，次要收进 Dropdown；危险操作红色 |
| 批量操作 | 选中后出现批量条；显示选中数量；支持全选当前页/全部筛选结果 |
| 详情 | 使用 Slide-over 抽屉，不离开列表；复杂对象用独立详情页 |
| 状态与审计 | 加载骨架、空态、错误重试；每个写操作记录 actor/IP/request_id/before/after |

通用列表能力：

- 分页（默认 20/页，可切 50/100）。
- 导出 CSV（受权限与行数上限限制，异步生成大文件）。
- 列显示/隐藏与顺序（个人偏好）。
- 键盘：`/` 聚焦筛选，`j/k` 移动行，`Enter` 打开详情。

## 5. 信息架构与页面清单

### 5.1 概览

| 页面 | URL | 权限 | 内容 |
|---|---|---|---|
| 仪表盘 | `/admin` | `admin.access` | KPI、趋势、模块卡片、系统健康、快捷操作 |

**KPI 卡片**：今日新增用户、今日主题/回复、DAU/WAU、待审数量、未处理举报、今日收入、支付成功率、7 日退款额。
**趋势图**：注册、内容、收入、举报（7/30 天切换）。
**模块卡片**（由模块贡献）：

| 模块 | 卡片 |
|---|---|
| auth | 新增用户、活跃用户、封禁中 |
| community | 主题/回复总量、待审内容、无回复主题 |
| moderation | 举报积压、中位处理时长、今日处理量 |
| gamification | 今日签到、发放积分、邀请转化 |
| billing | 今日收入、成功率、待对账差异、退款中 |
| search | 搜索量、零结果率、热词 |
| system | 数据库大小、队列积压、缓存命中率、磁盘余量 |

**快捷操作**：发公告、处理举报、审核队列、重建索引、清理缓存、备份。
**系统健康**：数据库连接、迁移版本、队列延迟、SSE 连接数、错误率（近 1 小时）。

| 主题 | `/admin/topics` | `admin.content.view` | 标题/板块/作者/状态/回复/浏览/最后回复 | 查看、编辑、置顶、精华、锁定、移动、删除、恢复 |

| 板块 | `/admin/categories` | `category.manage` | 名称/父级/可见性/主题数/排序 | 新建、编辑、排序、权限、归档、删除 |

**主题详情抽屉**：标题、作者、板块、标签、状态、统计、最近举报、操作历史、跳转前台。
**批量操作**：移动板块、加/移除标签、锁定、删除、恢复；执行前显示影响数量并二次确认。

|---|---|---|---|---|

| 用户组 | `/admin/groups` | `group.manage` | 名称/颜色/优先级/成员数/权限摘要 | 新建、编辑权限、排序、删除 |

### 5.4 审核

| 页面 | URL | 权限 | 内容 |
|---|---|---|---|
| 审核队列 | `/admin/review` | `moderation.queue.view` | 待审项、来源、优先级、等待时长、领取状态 |
| 举报列表 | `/admin/flags` | `flag.review` | 目标、举报人、原因、权重、状态 |
| 举报详情 | `/admin/flags/:id` | `flag.review` | 上下文、历史举报、相关用户、处理动作 |
| 申诉 | `/admin/appeals` | `moderation.appeal.handle` | 用户、处罚、申诉内容、状态（P2） |
| 审计日志 | `/admin/audit-logs` | `moderation.audit.view` | 时间、操作人、动作、目标、IP、request_id |

**审核工作流**：领取（防并发）→ 查看上下文 → 选择动作（通过/隐藏/删除/禁言/封禁/升级）→ 填写原因 → 提交 → 自动跳转下一条。
**快捷键**：`a` 通过、`r` 拒绝、`h` 隐藏、`b` 封禁、`n` 下一条（需二次确认）。
**审计详情**：展示 before/after JSON diff、关联 request_id、可跳转目标。

## 6. 命令面板

- `Ctrl/Cmd + K` 打开；支持页面跳转、用户搜索、订单搜索、主题搜索、操作执行。
- 结果分组并显示快捷键；无权限项不返回。
- 最近访问与常用操作置顶。
- 操作类结果（如“封禁用户”）先跳转目标详情，不直接执行。

## 7. 权限与审计

### 7.1 权限模型

- `admin.access`：进入后台的最低权限。
- 页面级权限：`admin.<domain>.<action>`，如 `admin.billing.refund`。
- 菜单项声明权限，渲染前过滤；服务端再次校验，前端隐藏不作为安全边界。
- 超级管理员拥有全部权限；权限变更实时生效（权限版本号缓存失效）。

### 7.2 审计要求

| 操作类型 | 记录内容 |
|---|---|
| 内容删除/恢复/移动/合并 | actor、目标、before/after、原因 |
| 用户禁言/封禁/改组 | actor、期限、原因、影响会话 |
| 设置修改 | 变更键、旧值、新值（密钥脱敏） |
| 退款/订单操作 | 金额、原因、渠道结果 |
| 渠道配置 | 变更字段（密钥只记“已更新”） |
| 登录后台 | 成功/失败、IP、UA |
| 数据导出/备份 | 范围、操作人、文件 |

审计日志不可删除；保留至少 1 年，可导出归档。

## 8. 后台交互规范

- 所有写操作按钮在执行中禁用并显示进度。
- 删除使用“移到回收站/软删除”，高危删除需输入确认词。
- 批量操作先展示影响范围与不可逆提示。
- 表格空态区分“无数据”和“筛选无结果”，后者提供重置。
- 错误提示包含 request_id，便于日志定位。
- 表单离开未保存时提示；设置页支持差异保存与恢复默认。
- 时间显示相对时间 + 悬停绝对时间；金额显示原币种。
- 长文本截断并可展开；敏感字段默认掩码。

## 9. 验收标准

1. 每个模块的菜单、页面、卡片均可通过 `AdminContribution` 注册，后台核心无需改动。
2. 无权限用户看不到菜单，直接访问返回 403 且写入审计。
3. 所有列表页具备筛选、分页、批量、详情抽屉、空/错/加载态。
4. 所有写操作有审计记录，包含 actor、IP、request_id、before/after。
5. 退款、删除板块、恢复备份等高危操作需二次确认并填写原因。
6. 后台在 1280px 与 768px 下均可用，移动端可完成审核与查看。
7. 仪表盘任一卡片失败不影响其他卡片，并显示可重试错误态。
