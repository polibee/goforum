# 生产部署 P0 修复

> 解决「生产模式无法全新安装」与「升级缺少迁移路径」两个上线阻断项，并让 schema 不完整时启动快速失败。

## 1. 全新生产安装自动建表

### 问题

生产模式启动走 `EnsureSchema` 只检查表、不建表；安装向导随后在空库上创建管理员，实际报错：

```
数据库连接失败：SQL logic error: no such table: settings (1)
```

### 修复

- 新增 `app.MigrateFresh`：仅当数据库没有用户时执行建表，避免误改已有安装。
- 安装向导在 `Open` 之前调用 `MigrateFresh`；已有用户时返回 409「该数据库已初始化，请直接登录。」
- 空库（或无 `users` 表）才允许建表；已存在用户的库不会被安装入口迁移。

## 2. 新增 `goforum migrate`

```bash
./goforum migrate
```

- 读取与运行时相同的配置（YAML → .env → 环境变量）。
- 打开数据库，按 `schema_migrations` 台账依次执行未应用迁移。
- 当前迁移：`0001 baseline_models`（基线建表）、`0002 legacy_subscriptions`（历史订阅拆分）。
- 迁移完成后再次执行 `EnsureSchema` 校验表和列。
- 成功输出 `database schema is up to date`。
- 已加入 `goforum help`。

版本化台账的细节见 `33-密钥加密与版本化迁移.md`。生产升级流程要求：

1. 先备份数据库；
2. 停应用或进入维护模式；
3. 执行 `goforum migrate`；
4. 启动新版本并做冒烟。

## 3. 生产启动快速失败

- `EnsureSchema` 现在同时检查**表和列**：缺表或缺列都会返回明确清单。
- 生产模式启动时还会校验 `schema_migrations` 台账：
  - 台账不存在或缺少当前版本的迁移 → `ErrSchemaIncomplete`，提示执行 `goforum migrate`；
  - 数据库为空 → 返回普通错误，进入安装向导；
  - 数据库已有用户但 schema/台账不完整 → `main` 直接退出，不再进入安装向导，也不继续提供会报错的页面。
- 错误示例：

```
database schema is incomplete: missing tables: email_send_logs
(run `goforum migrate` first)
```

- `Open` 失败时会关闭已打开的数据库与缓存句柄，避免 Windows 下文件被占用。

## 4. 模型清单统一

新增 `app.SchemaModels()`，构造与 `Open` 相同的功能模块清单并汇总：

- 平台表：`settings`、`setting_revisions`、`sessions`、`audit_logs`
- 全部功能模块模型：auth、community、media、engagement、messaging、notification、moderation、gamification、billing、site、ads
- 安装、迁移命令和启动校验共用同一份清单。

## 5. 验证

新增测试：

- `internal/app/schema_test.go`
  - `Migrate` 建表并重复执行保持幂等；
  - `MigrateFresh` 在已有用户时返回 `ErrDatabaseInitialized`；
  - 已有用户但缺表时 `Open` 返回 `ErrSchemaIncomplete`；
  - 空库不返回 `ErrSchemaIncomplete`，仍可进入安装向导。
- `internal/platform/db/db_test.go`
  - 缺表、缺列均能被 `EnsureSchema` 检出；
  - 补齐列后校验通过。

端到端实测：

1. `APP_ENV=production` + 空 SQLite：`POST /install` 返回 302 到 `/admin/login`，安装成功。
2. 删除 `email_send_logs` 后重启：进程退出并输出 `database schema is incomplete; run goforum migrate`，18090 未监听。
3. 执行 `./goforum-test migrate`：输出 `database schema is up to date`，表恢复。
4. 再次启动：`GET /login` 返回 200。

`go vet ./...` 与 `go test ./...` 全部通过。
