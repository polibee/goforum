## 3. 关键实现

### 3.1 互动

- `reactions`、`bookmarks`、`subscriptions` 均有 `(user_id,target_type,target_id[,reaction])` 唯一约束，切换用事务内查删/查增。
- 互动服务通过 community `contracts.Reader` 校验目标并取得作者/主题 ID，不直接访问 community 表。
- 计数由事件驱动：engagement 发布 `reaction.added/removed`、`bookmark.added/removed`，community 订阅后更新 `posts.like_count`、`topics.like_count`、`topics.bookmark_count`，负向更新带下限保护。
- 主题页通过 `contracts.EngagementReader` 注入初始状态；社区模块不 import engagement，避免循环依赖。

### 3.2 @提及与通知

- 正则 `@([\p{L}\p{N}_]{2,50})` 提取，批量 `FindByUsernames` 解析为用户 ID。
- 同一事件内同一用户最多一条通知：提及优先于回复。
- 通知事件 ID + 用户 ID 唯一，事件重放不重复。
- 偏好按类型存储 `notification_preferences(user_id,type,in_app)`；未配置时默认开启。
- 点赞通知由 `reaction.added` 触发，作者=操作者时跳过。

### 3.3 私信

- 一对一会话：查找双方共同参与的 direct 会话，存在则复用；否则事务创建会话与两个参与者。
- 未读数：以参与者 `last_read_at` 与消息创建时间比较；打开会话即更新为当前时间。
- 发送消息更新会话 `last_message_at/last_message_id`，并发布 `message.created`，通知服务按接收人偏好生成 `message.new`。
- 非参与者访问返回 404，避免探测。

### 3.4 三方言检索

- 统一投影 `search_documents`：`id/doc_type/topic_id/title/body/category_id/author_id/visibility/updated_at`。
- SQLite：`search_fts` FTS5 虚拟表，优先 `trigram` 分词（支持中文子串），失败降级 `unicode61`；查询用 `MATCH` + `bm25`。
- MySQL：`FULLTEXT(title,body) WITH PARSER ngram`，失败时尝试普通 FULLTEXT；查询 `MATCH ... AGAINST`。
- PostgreSQL：`search_vector tsvector` + GIN，查询 `plainto_tsquery/ts_rank`。
- 任一方言不可用或查询过短（SQLite <3 字符）时自动降级为 `LIKE`。
- 主题与回复分别建文档；检索结果按 `topic_id` 去重后回表加载主题，保持结果顺序。
- 公开检索只返回 `visibility=public`；删除/隐藏内容同步移除索引。

### 3.5 媒体

- 上传校验：大小、MIME、图片解码、个人配额。
- 缩略图：宽度 >480 时按 480 宽等比缩放，PNG 输出 PNG，其余输出 JPEG（质量 82）；写入 `upload_variants`。
- 上传响应返回 `thumb_url`；原图与缩略图均通过 `/uploads/...` 访问。
- 配额按 `SUM(size_bytes)` 计算，超过默认 500MB 拒绝。

## 4. 与设计的差异

| 设计 | M2 现状 | 计划 |
|---|---|---|
| 私信屏蔽与举报 | 未实现 | M2 余量/M3 |
| 头部私信未读数 | 仅会话列表内显示 | M2 余量 |
| 检索结果总数 | 以本次返回集合计算，非精确总数 | 后续加分页计数 |
| 索引重建 UI | 无，`Reindex` 为空实现 | M3 后台任务 |
| AVIF 缩略图 | 输出 JPEG/PNG | 依赖编码器，后续 |
| MySQL/PostgreSQL FTS | 代码路径已实现，本地仅验证 SQLite | CI 多库验证 |
