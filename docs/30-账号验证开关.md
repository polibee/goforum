# 账号验证开关

> 后台管理员可集中启停用户注册、找回密码、修改密码与换绑邮箱时的验证流程。设置保存后立即生效，无需重启。

## 1. 功能边界

本次把与「账号自助安全」相关的开关集中到后台「站点设置 → 账号验证」分组，避免散落在注册或邮件配置里：

| 设置键 | 默认 | 作用 |
|---|---|---|
| `site.registration.email_verification` | 开 | 注册邮箱验证。开启后新用户状态为 `pending_email`，点击邮件链接后转 `active`；关闭后注册即登录 |
| `site.verification.password_reset` | 开 | 找回密码。关闭后登录页隐藏「忘记密码」，`/forgot-password` 与 `/reset-password` 显示停用提示并拒绝请求 |
| `site.verification.password_change` | 开 | 自助修改密码。关闭后账号安全页隐藏密码表单，服务层同时拒绝提交 |
| `site.verification.password_change_verify` | 关 | 修改密码需邮箱验证码。开启后需先发送 6 位验证码到注册邮箱，10 分钟内有效 |
| `site.verification.email_change` | 开 | 自助修改邮箱。关闭后账号安全页隐藏换绑表单 |
| `site.verification.email_change_verify` | 开 | 换绑邮箱需邮件确认。关闭后验证当前密码即可立即生效 |
| `site.verification.email_daily_limit` | 10 | 单账号单日验证/安全邮件上限，0 表示不限制 |
| `site.verification.email_total_limit` | 50 | 单账号累计（永久）验证/安全邮件上限，0 表示不限制 |

设置分组位于「注册与登录」之后，权限沿用 `settings.registration`。所有改动通过 `settings.Store` 写入并记录审计与版本历史。

## 2. 服务层行为

### 2.1 注册邮箱验证

- `Register` 读取开关决定新账号状态：开启 → `pending_email` 并发送验证邮件；关闭 → 直接 `active`。
- `Authenticate` 同样读取开关：
  - 开启：`pending_email` 与未验证的 `active` 账号均拒绝登录；
  - 关闭：历史 `pending_email` 账号在下次登录时自动转为 `active`，避免管理员逐个解锁。
- `ResendVerification` 在开关关闭时直接返回，不再发送邮件。

### 2.2 找回密码

- 登录页仅在开关开启时显示「忘记密码？」
- `GET /forgot-password` / `GET /reset-password` 在关闭时渲染停用说明，不显示表单。
- `POST /forgot-password` 返回 403 停用提示。
- 服务层 `RequestPasswordReset` / `ResetPassword` 双重校验，直接调用也会被拒绝。

### 2.3 修改密码与邮箱验证码

- 新增 `POST /settings/security/password/code`，登录用户可发送验证码；路由限流 5 次 / 10 分钟。
- 验证码为 6 位数字，仅绑定当前用户，`email_tokens` 中 purpose 为 `password_change`，有效期 10 分钟。
- 重复发送会将旧验证码标记为已使用，只保留最新一条。
- `ChangePassword` 在开启验证时要求 `code`：
  - 格式必须为 6 位数字；
  - 必须匹配当前用户未过期、未使用的验证码；
  - 修改成功后同一事务内作废该用户全部未使用的密码验证码，验证码单次有效。
- 关闭「允许用户修改密码」时，账号安全页显示停用说明，服务层拒绝提交。

### 2.4 换绑邮箱

- 「允许用户修改邮箱」关闭时，表单隐藏，`RequestEmailChange` / `ConfirmEmailChange` 均返回 403。
- 「修改邮箱需邮件确认」开启时保持原有流程：向新邮箱发送 1 小时有效的确认链接，同时通知旧邮箱。
- 关闭确认后：验证当前密码并检查唯一性，直接更新邮箱与 `email_verified_at`，同时向旧邮箱发送变更通知。

### 2.5 邮件次数限制

- `email_send_logs` 表按 `(user_id, created_at)` 记录每次账号触发的验证/安全邮件，不存储邮件正文或收件地址。
- 发送前检查两项配额：
  - 单日上限：按站点时区（`site.general.timezone`）计算当天 0 点，统计当天记录；
  - 累计上限：统计该账号全部历史记录，不随日期重置。
- 覆盖范围：注册验证、重发验证、找回密码、修改密码验证码、换绑邮箱确认/通知；管理员或系统事件邮件不占用用户配额。
- 超出上限时：
  - 已登录操作（修改密码验证码、换绑邮箱）直接显示错误；
  - 找回密码、重发验证等公开入口保持统一成功文案，静默不发送，避免账号枚举。
- 两个值都设为 0 时不限制，也不再写入日志。
- 配额检查失败（例如旧库尚未迁移出 `email_send_logs`）时放行发送，避免影响密码找回；迁移完成后自动恢复保护。
- 并发请求可能极少量超出上限，外层仍有按 IP/路由的中间件限流，两层共同抑制刷接口。

## 3. 页面与交互

### 账号安全页

- 邮箱卡片显示「已验证 / 未验证」徽标；未验证且注册验证开启时提供「重新发送验证邮件」。
- 邮箱表单按开关切换提示与按钮文案：
  - 需确认：「发送验证邮件」；
  - 无需确认：「保存新邮箱」，提示保存后立即生效。
- 修改密码卡片：
  - 关闭时只显示停用说明；
  - 开启验证码时展示发送验证码按钮、6 位验证码输入框，密码最小长度读取 `site.registration.password_min`。
- 验证码发送成功显示 `?code_sent=1` 提示。

### 登录与注册页

- 登录页按开关隐藏「忘记密码？」。
- 注册页在开启邮箱验证时，在邮箱输入框下提示「注册后需点击验证邮件中的链接完成验证。」

### 后台设置页

- 新增「账号验证」分组，包含 6 个开关与 2 个邮件次数上限，每项带中文说明。
- 分组图标、英文标签与说明同步补齐，`en-US` 后台界面可完整显示。

## 4. 安全考量

- 前端隐藏不是安全边界：所有开关在服务层再次校验。
- 修改密码验证码绑定 `user_id`，避免拿到其他账号的令牌；哈希后存储，不保存明文。
- 验证码与重置链接都使用现有 `email_tokens` 表，保持单次使用与过期语义。
- 关闭验证不会放宽密码最小长度、当前密码校验、邮箱唯一性等基础约束。
- 关闭「找回密码」/「修改密码」不会删除已有令牌；重新开启后未过期令牌仍可使用，符合管理员临时停用的预期。

## 5. 测试与验证

新增 `internal/modules/auth/verification_test.go`，覆盖：

1. 关闭注册验证后新账号直接激活、不发送验证邮件；历史 `pending_email` 账号可登录并自动转正。
2. 关闭找回密码后请求与重置均被拒绝，重新开启后未使用令牌恢复可用。
3. 关闭自助修改密码后服务层拒绝，重新开启后正常。
4. 修改密码验证码：缺码、错码、正确码、单次使用。
5. 关闭换绑邮箱后拒绝；关闭“需邮件确认”后验证当前密码即立即生效。

新增 `internal/modules/auth/quota_test.go`，覆盖：

1. 单日上限：第 3 次请求被拒绝且不发送邮件。
2. 累计上限：超过永久次数后拒绝。
3. 跨天重置：昨天的记录不占用今天的额度。
4. 注册验证与重发验证计入累计次数。
5. 修改密码验证码、直接换绑邮箱均受配额约束。
6. 两项均为 0 时不限制且不写日志。

验证结果：

- `go test ./...` 全部通过。
- 本地预览实例启动后实测：
  - 关闭四项开关后登录页隐藏忘记密码、注册页隐藏验证提示、账号安全页隐藏密码与邮箱表单；
  - 直接 POST 找回密码返回 403 停用提示，直接 POST 修改密码返回停用错误；
  - 开启验证码后账号安全页出现验证码输入框，发送接口返回 `?code_sent=1` 并在 `email_tokens` 写入 `password_change` 记录；
  - 恢复默认后前台入口与表单正常回显；
  - 单日上限设为 2 后连续请求找回密码 3 次，仅生成 2 条 `email_send_logs` 与 2 个重置令牌，第 3 次保持统一成功文案；累计上限设为 2 时继续请求也不再发送。
