## 3. 关键实现

### 3.1 权限

- `groups.permissions_json` 保存权限键数组。
- 登录会话加载时调用 `PermissionsOf`：超管直接放行；有组则取并集；无组回退 `DefaultPermissions`。
- **注意**：把用户加入显式组后，默认权限不再自动叠加；需要同时保留“成员”组，或在组内显式勾选所需权限。
- 后台权限编辑器按权限键分组展示，保存为差异全量覆盖。

### 3.2 信任等级

- 阈值设置：`auth.trust.tl1_*`、`tl2_*`、`tl3_*`。
- 计算依据：注册天数、可见回复数、帖子获赞数。
- TL4 不参与自动计算；管理员可在用户详情手动设置 0–4。
- 启动后台协程每小时重算一次；管理操作写入审计。

### 3.3 审核

- 举报写入 `flags`，同时创建/复用 `review_queue` 项；`(reporter,target_type,target_id)` 与 `(item_type,item_id)` 唯一，天然幂等。
- 自动隐藏阈值来自 `moderation.auto_hide_flags`。
- 队列优先级 = 举报数量；领取使用 CAS，防止并发重复处理。
- 处理动作：驳回、隐藏、删除、恢复/通过、禁言、封禁；结果写审计。
- 新用户/敏感词转审核的主题或回复以 `pending`/`hidden` 状态创建，作者与版主可见，其它用户不可见。

### 3.4 敏感词

- 匹配方式：包含（默认）、完全匹配、正则。
- 动作：`block` 直接拒绝发布；`review` 转入审核队列。
- 正则创建时预编译校验，避免运行期错误。

### 3.5 私信

- 屏蔽关系双向生效：任一方屏蔽后，双方都不能发起新会话，也不能向对方发送消息。
- 发送前校验屏蔽，避免“报错但消息已落库”。
- 未读总数由各会话 `last_read_at` 汇总，头部显示角标。

### 3.6 索引重建

- 先清空 `search_documents` 与 SQLite FTS 表，再遍历公开主题与可见回复重建。
- 后台入口返回重建文档数；重建动作写审计。

## 6. M4 入口

1. **积分与等级**：积分规则、流水、余额、等级。
2. **签到与邀请**：连续签到、邀请码、配额。
3. **徽章与抽奖**：徽章规则、抽奖与开奖审计。
4. **悬赏托管**：冻结、结算、退款。
5. **M3 余量**：主题合并/拆分、分类版主、申诉、敏感词替换、审计时间筛选。
