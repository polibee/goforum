# 11 安全与权限设计

## 1. 威胁模型与目标

| 威胁 | 典型场景 | 主要防线 |
|---|---|---|
| 账号接管 | 撞库、弱密码、会话劫持 | Argon2id、2FA、限流、会话轮换、设备管理 |
| 越权访问 | 读取私有板块、操作他人内容 | 默认拒绝、资源级策略、服务端二次校验 |
| 内容注入 | XSS、恶意 HTML、SVG | 白名单清洗、CSP、上传重编码 |
| 数据泄露 | SQL 注入、错误页泄露堆栈 | 参数化查询、统一错误、日志脱敏 |
| 垃圾与滥用 | 刷帖、广告、批量注册 | 信任等级、频率限制、新用户审核、验证码 |
| 支付欺诈 | 金额篡改、回调伪造、重复入账 | 验签、金额校验、幂等、对账 |
| 供应链 | 依赖漏洞、恶意镜像 | 版本锁定、漏洞扫描、镜像签名 |
| 内部风险 | 管理员滥用、密钥泄露 | 最小权限、审计、密钥轮换、二次确认 |

安全基线：OWASP ASVS L2；所有安全决策默认拒绝（deny by default）。

## 2. 认证

### 2.1 密码

- 算法：**Argon2id**，参数 `m=64MB, t=3, p=2`（按部署硬件压测后调整）。
- 每个密码独立 16 字节随机盐；输出包含参数，便于升级后登录时重哈希。
- 密码策略：最小长度 10，禁止常见弱密码表；不强制特殊字符组合。
- 修改密码需验证当前密码；重置密码后失效全部会话。
- 禁止在日志、审计、错误信息中出现明文密码或哈希。

### 2.2 会话

| 项 | 设计 |
|---|---|
| Cookie | `gf_session`，HttpOnly、Secure、SameSite=Lax、Path=/ |
| 令牌 | 256 位随机，数据库只存 SHA-256 哈希 |
| 轮换 | 登录成功、权限提升、修改密码后轮换 |
| 过期 | 空闲 30 分钟（可配置）+ 绝对 30 天 |
| 撤销 | 单设备、全部设备、封禁立即撤销 |
| 绑定 | 记录 IP/UA 仅用于展示与风控，不强制绑定（避免移动网络误伤） |

### 2.3 2FA

当前实现（2026-11-10，详见 `32-管理员TOTP两步验证.md`）：

- TOTP：SHA-1、6 位、30 秒步长、允许前后各 1 个时间步；同一时间步验证码不可重放。
- 密钥使用 `APP_KEY` 派生的 AES-256-GCM 加密存储；启用时要求输入一次验证码确认。
- 恢复码 10 个，一次性，仅存 SHA-256 哈希，启用成功页展示一次。
- 策略：`off` / `superadmin`（默认）/ `admins`；已启用 2FA 的账号始终需要验证码。
- `/login/2fa` 限流 10 次 / 5 分钟；绑定接口 10 次 / 10 分钟；关闭接口 5 次 / 10 分钟。
- 未启用但策略要求的管理员：登录后直接进入绑定页，后台路由由中间件再次拦截。
- 仍有后续项：挑战失败锁定与邮件确认尚未实现，目前依赖 IP/路由限流。

### 2.4 第三方登录（OAuth）

- 使用 state + PKCE；state 一次性并绑定会话。
- 仅接受已验证邮箱；同一邮箱自动合并需用户确认，禁止静默合并。
- 记录 `provider + provider_uid` 唯一；解绑需至少保留一种登录方式。
- 回调地址白名单，禁止开放重定向。

### 2.5 API Token

- 格式 `gf_pat_<随机>`，只显示一次，存哈希。
- Scope：`read` / `write` / `admin`（按需细分到资源）。
- 支持过期时间与最后使用时间；可单独撤销。
- Token 请求不享受 Cookie 会话的 CSRF 豁免逻辑，但需 Bearer 校验。

### 2.6 登录防护

- 失败计数：账号 + IP 双维度；5 次失败锁定 15 分钟（可配置）。
- 统一错误文案，不区分“账号不存在/密码错误”。
- 注册、找回密码同样返回统一成功文案，防止账号枚举。
- 异常登录（新国家/新设备）可发提醒邮件（P1）。

## 3. 授权模型

### 3.1 双轨制

1. **用户组（RBAC）**：权限集合，用户可属于多个组，权限取并集；支持带过期时间的临时组（VIP）。
2. **信任等级（TL0–TL4）**：基于行为自动晋升，提供“社区信任”维度的能力门槛。

最终判定：`允许 = 组权限 ∧ 信任等级 ∧ 板块覆盖 ∧ 资源状态 ∧ 所有权/版主身份`，任一不满足即拒绝。

### 3.2 权限键目录

| 域 | 权限键 |
|---|---|
| 内容 | `topic.create` `topic.reply` `topic.edit_own` `topic.edit_any` `topic.delete_own` `topic.delete_any` `topic.moderate` `topic.pin` `topic.feature` `topic.lock` `topic.move` `topic.merge` `topic.split` `post.hide` `post.restore` |
| 板块/标签 | `category.manage` `tag.manage` |
| 互动 | `reaction.create` `bookmark.create` `subscription.create` `share.create` |
| 私信 | `message.send` `message.read` `message.block` `admin.message.view` |
| 举报/审核 | `flag.create` `flag.review` `moderation.queue.view` `moderation.action` `moderation.word.manage` `moderation.audit.view` `moderation.appeal.handle` |
| 用户 | `user.ban` `user.suspend` `group.manage` `admin.user.view` |
| 运营 | `bounty.create` `lottery.create` `admin.gamification.manage` `admin.invite.view` |
| 商业化 | `admin.billing.view` `admin.billing.manage` `admin.billing.refund` `admin.billing.channel` |
| 系统 | `admin.access` `admin.content.view` `admin.media.view` `admin.system` `settings.read` `settings.write` `settings.<group>` |

规则：键名稳定、全局唯一、格式 `domain.action`；新增权限必须登记到模块 manifest 与本文档。

### 3.3 信任等级

| 等级 | 名称 | 晋升条件（默认，可配置） | 主要能力 |
|---|---|---|---|
| TL0 | 新用户 | 注册即得 | 回复受限、外链禁止、内容进审核、私信受限 |
| TL1 | 基础用户 | 活跃 1 天、读过 1 个主题、发过 1 条回复 | 可发主题、上传头像、外链需审核 |
| TL2 | 成员 | 活跃 15 天、回复 3 个主题、获得 1 次点赞 | 免审发帖、上传附件、举报、私信 |
| TL3 | 常驻 | 近 100 天活跃 50 天、读 1000 帖、获 20 赞 | 更高频率、可编辑 Wiki 帖（可配置）、参与治理投票 |
| TL4 | 领袖 | 管理员手动授予 | 版主级轻量权限（隐藏/关闭，可配置） |

- 晋升与降级由定时任务计算，阈值来自设置；变更发通知。
- 封禁/严重违规可降级；降级不删除历史内容。
- TL 只作为门槛之一，不能绕过组权限。

### 3.4 权限矩阵（摘要）

| 操作 | 游客 | TL0 | TL1 | TL2 | TL3 | 版主 | 管理员 | 超管 |
|---|---|---|---|---|---|---|---|---|
| 浏览公开内容 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 发主题 | ❌ | ⚠️审核 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 回复 | ❌ | ⚠️审核 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 上传附件 | ❌ | ❌ | 头像 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 私信 | ❌ | ⚠️受限 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 举报 | ❌ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 隐藏/删除内容 | ❌ | ❌ | ❌ | ❌ | ❌ | ✅ | ✅ | ✅ |
| 封禁用户 | ❌ | ❌ | ❌ | ❌ | ❌ | 禁言 | ✅ | ✅ |
| 审核队列 | ❌ | ❌ | ❌ | ❌ | ❌ | ✅ | ✅ | ✅ |

| 退款/渠道 | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | 部分 | ✅ |

### 3.5 板块覆盖

- 板块可设置：可见性（public/private/unlisted）、最低信任等级、发帖需审核、只读、慢速模式。
- 板块权限按用户组覆盖全局权限；私有板块对无权限用户返回 **404**。
- 版主按板块授予（`category_moderators`），仅在该板块内有效。

### 3.6 判定实现

```go
func (p *Policy) Can(ctx context.Context, user *User, action string, res Resource) bool {
    if user == nil {
        return p.roleAllows(guest, action)
    }
    if user.IsSuperAdmin {
        return true
    }
    if !p.groupAllows(user, action) {
        return false
    }
    if !p.trustAllows(user, action) {
        return false
    }
    if res != nil && !p.resourceAllows(user, action, res) {
        return false
    }
    return true
}
```

- 权限缓存按 `user_id + permission_version`；组/权限变更后版本 +1。
- 前端 `hasPermission` 只用于显隐；所有写操作在 Service 层再次校验。
- 禁止在 Handler 中手写权限字符串散落判断，统一走 Policy。

## 4. 输入与输出安全

### 4.1 输入校验

- 所有输入在 Handler 绑定后立即校验：类型、长度、枚举、范围、格式。
- 富文本先按 Markdown 解析，再经 HTML 白名单清洗。
- 文件上传按 9 节处理。
- URL 参数：`next`/`redirect` 仅允许站内相对路径，禁止 `//evil.com`。
- 查询参数枚举非法值返回 `validation.invalid`，不静默降级。

### 4.2 XSS

- 模板默认转义；只有经过清洗的 `cooked_html` 使用 `template.HTML`。
- 清洗规则（bluemonday）：
  - 允许：`p br strong em del code pre blockquote ul ol li a img h1-h6 table thead tbody tr th td hr span`
  - 属性：`href src alt title class`（`class` 仅限白名单前缀 `language-`）
  - 链接：仅 `http/https/mailto`；外链加 `rel="nofollow ugc noopener"`；低信任用户强制 nofollow。
  - 图片：仅 `http/https`，禁止 `data:`（除受控表情）。
  - 禁止：`script style iframe object embed form input svg math`。
- 代码块高亮在服务端生成，类名白名单。
- CSP 兜底：`script-src 'self' 'nonce-...'`，禁止 `unsafe-inline`/`unsafe-eval`（使用 Alpine CSP build）。
- 用户自定义 CSS/JS 仅超管，且经审核与 nonce 注入。

### 4.3 SQL 注入

- 一律使用 GORM 参数绑定；禁止字符串拼接 SQL。
- 原生 SQL 仅存在于方言层，必须使用占位符；动态列名来自白名单。
- 排序字段、表名、方向均使用枚举映射，不直接使用用户输入。

### 4.4 CSRF

- Cookie 会话的写请求必须校验 CSRF Token（同步令牌，绑定会话）。
- 同时校验 `Origin`/`Referer` 与站点域名一致。
- `SameSite=Lax` 作为第二道防线。
- 支付回调、Webhook 等无会话接口不使用 CSRF，改用签名校验。
- 登出使用 POST，避免被 GET 触发。

### 4.5 点击劫持与头部

```
Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-<n>'; style-src 'self' 'nonce-<n>';
  img-src 'self' data: blob: https://cdn.example.com; connect-src 'self'; font-src 'self';
  frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
X-Frame-Options: DENY
Cross-Origin-Opener-Policy: same-origin
```

### 4.6 SSRF 与出站请求

- Webhook、OAuth、图片抓取等出站请求必须：
  - 仅允许 `http/https`；
  - 解析 DNS 后拒绝私有网段（10/8、172.16/12、192.168/16、127/8、169.254/16、::1、fc00::/7）；
  - 禁止跟随到内网的重定向；
  - 设置超时与响应大小上限。
- 用户提供的 URL 不作为服务端抓取目标（除明确功能且经上述校验）。

### 4.7 其他

- **开放重定向**：`next` 仅站内相对路径；外链跳转页使用签名。
- **模板注入**：模板名来自固定枚举，不接受用户输入。
- **反序列化**：仅 JSON；禁止 gob/自定义二进制。
- **路径穿越**：存储键由服务端生成 ULID，不使用原始文件名作为路径。
- **HTTP 方法**：写操作仅 POST/PATCH/DELETE；GET 无副作用。
- **错误信息**：生产环境不返回堆栈、SQL、文件路径；统一 `internal.error` + request_id。

## 5. 上传安全

| 检查 | 要求 |
|---|---|
| 大小 | 单文件上限（默认 20MB），分片上传限制总大小 |
| 类型 | 扩展名白名单 + MIME 嗅探双重校验 |
| 图片 | 解码验证；限制像素总数（防解压炸弹）；重编码为 WebP/AVIF；剥离 EXIF |
| 危险类型 | 禁止 SVG、HTML、JS、可执行文件、压缩包内嵌套可执行（可配置） |
| 文件名 | 服务端生成；原始名仅作展示并转义 |
| 存储 | 独立目录/域名；禁止执行权限；私有附件签名 URL |
| 病毒 | 可选 ClamAV 扫描；扫描失败拒绝或隔离 |
| 引用 | 记录引用关系；删除内容后延迟清理孤儿文件 |
| 配额 | 按用户/用户组限制总量与单日上传数 |

## 6. 频率限制与反垃圾

### 6.1 限流

- 维度：IP、用户、路由、动作。
- 默认值见 05 文档第 3.3 节；登录、注册、找回密码、上传、下单、回调单独配置。
- 超限返回 429 + `Retry-After`，并记录风控日志。

### 6.2 反垃圾规则

| 规则 | 动作 |
|---|---|
| 新用户（TL0/注册 < N 天）发帖 | 进审核队列 |
| 低信任用户外链 | 禁止或 nofollow + 审核 |
| 短时间内重复内容 | 拒绝并提示 |
| 标题/正文含敏感词 | 拦截 / 转审核 / 替换（按词配置） |
| 举报达到阈值 | 自动隐藏，进队列 |
| 注册频率异常（同 IP/同段） | 验证码 / 拒绝 |
| 私信批量发送 | 限流 + 新用户限制 |
| 账号被多次处罚 | 降级、限制发帖、封禁 |

可选增强：Turnstile/hCaptcha、蜜罐字段、IP 信誉库、邮箱域名黑名单、设备指纹（需注意隐私合规）。

## 7. 支付安全（摘要）

> 完整设计见 [12-支付网关与虚拟经济设计](./12-支付网关与虚拟经济设计.md)。

- 不接触卡号，仅跳转/二维码/Hosted 页面。
- 回调必须验签，并校验订单、渠道、金额、币种。
- 订单状态迁移使用 CAS；回调与账本幂等。
- 退款需权限 + 原因 + 二次确认；全额/部分退款均写审计。
- 渠道密钥加密存储、掩码显示、支持轮换。
- 每日对账，差异告警；异常订单人工复核。

## 8. 密钥与配置安全

- 密钥来源优先级：环境变量 > 加密配置；禁止写入代码与日志。
- 加密算法：AES-256-GCM；密钥来自 `GF_SECRET_KEY`，支持轮换（新旧密钥并存解密）。
- 密钥字段：SMTP 密码、OAuth secret、S3 密钥、支付渠道密钥、TOTP 加密密钥。
- 后台只显示“已配置/未配置”，不提供回显；更新时留空表示不变。
- 配置文件权限 0600；容器内以非 root 运行；只读文件系统（除数据目录）。

## 9. 审计与监控

### 9.1 审计

- 记录：时间、actor、动作、目标、before/after、IP、UA、request_id、原因。
- 覆盖：登录后台、权限变更、内容管理、用户处罚、设置修改、退款、渠道配置、数据导出、备份恢复。
- 不可删除、不可修改；保留 ≥ 1 年，可导出归档。
- 敏感字段（密码、密钥、Token）不写入审计。

### 9.2 监控告警

| 指标 | 告警条件 |
|---|---|
| 登录失败率 | 5 分钟内 > 100 次或单账号 > 10 次 |
| 权限拒绝 | 单用户 5 分钟内 > 50 次 |
| 5xx 错误率 | 5 分钟内 > 1% |
| 支付失败率 | 15 分钟内 > 10% |
| 回调验签失败 | 任意连续 5 次 |
| 对账差异 | 日终存在未解释差异 |
| 队列积压 | 超过 1000 或延迟 > 5 分钟 |
| 磁盘/数据库 | 使用率 > 85% |
| 上传拒绝率 | 突增 3 倍（可能攻击） |

## 10. 隐私与合规

- 最小化采集：仅必要信息；IP 保留期可配置（默认 90 天），到期脱敏。
- 用户可导出个人数据（资料、主题、回复、订单）与申请注销。
- 注销：7 天冷静期；到期后匿名化内容（保留“已注销用户”）或按配置删除。
- Cookie：仅使用必要会话 Cookie；统计脚本需说明并遵守当地法规。
- 隐私政策、用户协议、社区规则作为内置页面模板，部署方自行完善。
- 未成年人、内容审核、备案等合规要求由部署方按所在地法律落实。

## 11. 供应链与依赖

- Go 依赖锁定 `go.sum`；CI 运行 `govulncheck`。
- 基础镜像使用固定 digest；非 root；最小镜像。
- 前端依赖锁定版本；构建产物校验哈希。
- 禁止从不可信源加载脚本；第三方脚本需 CSP 白名单与评审。
- 发布产物签名/校验和；升级前备份。

## 12. 事件响应

| 级别 | 示例 | 动作 |
|---|---|---|
| P0 | 密钥泄露、支付被刷、数据泄露 | 立即轮换密钥、封禁入口、保留证据、通知相关方 |
| P1 | 大规模垃圾、越权漏洞 | 限流/关闭功能、热修复、审计影响范围 |
| P2 | 单点异常、可疑登录 | 调查、通知用户、加强验证 |

预案：保留日志与快照 → 定位入口 → 止血（开关/限流/下线）→ 修复 → 复盘 → 补充测试。

## 13. 安全测试清单

- [ ] 认证：撞库限流、会话固定、2FA 绕过、找回密码枚举
- [ ] 授权：水平越权（他人订单/私信）、垂直越权（后台接口）、私有板块泄露
- [ ] 注入：XSS（主题/回复/签名/用户名）、SQL 注入、模板注入、CSRF
- [ ] 上传：伪造 MIME、双扩展名、SVG/HTML、超大图、路径穿越
- [ ] 支付：金额篡改、回调伪造/重放、并发重复入账、退款越权
- [ ] SSRF：Webhook、OAuth、图片抓取
- [ ] 头部：CSP、HSTS、XFO、Referrer-Policy
- [ ] 限流：登录、注册、发帖、上传、下单
- [ ] 审计：管理操作全覆盖、敏感字段脱敏
- [ ] 依赖：`govulncheck` 无高危、镜像扫描通过

## 14. 验收标准

1. 默认拒绝：未授权访问任何写接口均返回 401/403，私有资源返回 404。
2. 所有管理写操作有审计，且不可删除。
3. 主题/回复中的恶意 HTML、SVG、`javascript:` 链接均被清除。
4. 严格 CSP 下前台与后台功能正常（无 `unsafe-eval`）。
5. 登录、注册、找回密码不存在账号枚举。
6. 支付回调伪造、金额篡改、重复回调均被拒绝或幂等处理。
7. 上传的伪造可执行文件被拒绝，图片元数据被剥离。
8. 限流阈值生效，429 响应带 `Retry-After`。
9. 密钥不出现在日志、审计、接口响应与前端源码中。
10. 安全测试清单全部通过，无高危/严重漏洞。
