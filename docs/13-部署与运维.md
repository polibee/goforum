# 13 部署与运维

## 1. 部署形态

| 形态 | 适用 | 依赖 | 说明 |
|---|---|---|---|
| 单二进制 + SQLite | 个人/小社区 | 无 | 零外部依赖，最简单 |
| 单二进制 + MySQL/PG | 中型社区 | 数据库 | 应用与数据库分离 |
| Docker Compose | 标准生产 | DB + 可选 Redis/S3 | 一键启动，便于升级 |
| 多实例 | 大型社区 | DB + Redis + 对象存储 | 无状态应用 + 共享存储 |

约束：**SQLite 只允许单实例**；多实例必须使用 MySQL/PostgreSQL + 共享 Redis（缓存/广播）+ 对象存储。

## 2. 构建

```makefile
VERSION := $(shell git describe --tags --always --dirty)
LDFLAGS := -s -w -X main.version=$(VERSION)

assets:
	npm ci
	npx tailwindcss -i web/css/app.css -o web/static/dist/app.css --minify
	npx esbuild web/js/app.js --bundle --minify --outfile=web/static/dist/app.js
	go run ./cmd/assetmanifest

build: assets
	CGO_ENABLED=0 go build -trimpath -ldflags "$(LDFLAGS)" -o bin/goforum ./cmd/goforum

test:
	go test ./...
```

- `CGO_ENABLED=0`：SQLite 使用纯 Go 驱动（`glebarez/sqlite`），便于交叉编译与 Alpine 镜像。
- 模板与 `web/static/dist` 通过 `embed.FS` 内嵌；`--assets-dir` 可覆盖为外部目录（主题开发）。
- 版本号注入 `main.version`，`/healthz` 与后台“关于”展示。

## 3. 配置

优先级：默认值 < 数据库设置 < 环境变量 < 启动参数。基础设施连接信息只从环境变量/配置文件读取。

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `GF_ENV` | `production` | production/staging/development |
| `GF_HTTP_ADDR` | `:8080` | 监听地址 |
| `GF_BASE_URL` | — | 站点对外 URL（含 scheme） |
| `GF_DB_DRIVER` | `sqlite` | sqlite/mysql/postgres |
| `GF_DB_DSN` | `./data/goforum.db` | 连接串 |
| `GF_DB_MAX_OPEN` | `25` | 最大连接数 |
| `GF_DB_MAX_IDLE` | `10` | 空闲连接 |
| `GF_DB_CONN_MAX_LIFETIME` | `30m` | 连接寿命 |
| `GF_REDIS_URL` | — | 启用 Redis 缓存/广播 |
| `GF_STORAGE_DRIVER` | `local` | local/s3 |
| `GF_STORAGE_LOCAL_PATH` | `./data/uploads` | 本地目录 |
| `GF_S3_ENDPOINT` | — | S3/OSS/MinIO |
| `GF_S3_BUCKET` | — | 桶 |
| `GF_S3_ACCESS_KEY` | — | AK |
| `GF_S3_SECRET_KEY` | — | SK |
| `GF_S3_REGION` | — | 区域 |
| `GF_SECRET_KEY` | — | AES-256-GCM 主密钥（32 字节 base64） |
| `GF_SMTP_HOST` / `PORT` / `USER` / `PASS` / `FROM` | — | 邮件 |
| `GF_LOG_LEVEL` | `info` | debug/info/warn/error |
| `GF_LOG_FORMAT` | `json` | json/text |
| `GF_TRUSTED_PROXIES` | — | 反代 CIDR，逗号分隔 |
| `GF_WORKER_ENABLED` | `true` | 是否运行定时任务/队列 |
| `GF_SSE_MAX_CONN` | `10000` | SSE 连接上限 |
| `GF_METRICS_ENABLED` | `false` | Prometheus 指标 |


## 4. 三种数据库部署

### 4.1 SQLite

- 驱动：纯 Go（`glebarez/sqlite`），无需 CGO。
- DSN 参数：`?_pragma=journal_mode(WAL)&_pragma=busy_timeout(5000)&_pragma=foreign_keys(1)&_pragma=synchronous(NORMAL)`
- 文件放在本地 SSD，**禁止网络文件系统**（NFS/SMB 会导致锁异常）。
- 单写者：写事务保持短小；高并发写场景改用 MySQL/PG。
- 备份：`VACUUM INTO 'backup.db'` 或 `sqlite3 .backup`，不要直接复制正在写入的文件。
- 上限建议：≤ 20 万主题、≤ 50 万用户；超过后迁移。

### 4.2 MySQL

- 版本 8.0+；`utf8mb4` + `utf8mb4_0900_ai_ci`；InnoDB。
- DSN：`user:pass@tcp(db:3306)/goforum?charset=utf8mb4&parseTime=True&loc=UTC&multiStatements=false`
- `max_connections` ≥ 应用连接池总和的 1.5 倍；慢查询日志开启。
- 全文检索使用 ngram parser（`ngram_token_size=2`），需在初始化时创建 FULLTEXT 索引。
- 大表变更使用在线 DDL（`ALGORITHM=INPLACE`）或 gh-ost（超大规模）。

### 4.3 PostgreSQL

- 版本 14+；UTF8；`TimeZone=UTC`。
- DSN：`host=db user=goforum password=*** dbname=goforum sslmode=require TimeZone=UTC`
- JSONB、GIN、tsvector 原生支持；中文分词可用 `zhparser`（可选）。
- 连接池：应用侧 `max_open` 控制；PgBouncer 使用 transaction 模式时注意 prepared statements。
- 自动 vacuum 监控；大表写入关注膨胀。

### 4.4 数据库迁移

- 生产启动不执行 `AutoMigrate`；启动前用 `EnsureSchema` 校验表和列，并校验 `schema_migrations` 台账，缺失则拒绝启动。
- 当前迁移命令为 `./goforum migrate`：按版本顺序执行未应用迁移，写入 `schema_migrations`，随后再次校验 schema。
- 已注册迁移：`0001 baseline_models`（当前模型基线）、`0002 legacy_subscriptions`（历史订阅拆分）。
- 迁移前必须先备份；生产升级建议停应用或进入维护模式后执行。
- 新迁移追加到 `internal/app/schema.go` 的 `schemaMigrations`，版本号递增；不要修改已发布迁移。
- 多实例：迁移由单独 Job/首实例执行；当前尚未实现数据库 advisory lock，需人工保证同一时间只有一个实例执行。

## 5. Docker

```dockerfile
FROM node:22-alpine AS assets
WORKDIR /src
COPY package*.json ./
RUN npm ci
COPY web ./web
RUN npx tailwindcss -i web/css/app.css -o web/static/dist/app.css --minify && \
    npx esbuild web/js/app.js --bundle --minify --outfile=web/static/dist/app.js

FROM golang:1.23-alpine AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
COPY --from=assets /src/web/static/dist ./web/static/dist
RUN CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o /out/goforum ./cmd/goforum

FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=build /out/goforum /goforum
COPY --from=build /src/web/static/dist /web/static/dist
EXPOSE 8080
USER nonroot:nonroot
ENTRYPOINT ["/goforum"]
```

- 非 root、只读根文件系统；`/data` 挂载可写卷。
- 健康检查：`GET /healthz`。
- 时区数据：distroless 已含；如需自定义时区挂载 `zoneinfo`。

### 5.1 Compose 示例

```yaml
services:
  app:
    image: goforum:latest
    environment:
      GF_ENV: production
      GF_BASE_URL: https://forum.example.com
      GF_DB_DRIVER: postgres
      GF_DB_DSN: host=db user=goforum password=${DB_PASS} dbname=goforum sslmode=disable TimeZone=UTC
      GF_REDIS_URL: redis://redis:6379/0
      GF_SECRET_KEY: ${GF_SECRET_KEY}
    volumes:
      - uploads:/data/uploads
    ports: ["8080:8080"]
    depends_on: [db, redis]
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: goforum
      POSTGRES_USER: goforum
      POSTGRES_PASSWORD: ${DB_PASS}
    volumes: [pgdata:/var/lib/postgresql/data]
  redis:
    image: redis:7-alpine
    command: ["redis-server", "--appendonly", "yes"]
    volumes: [redisdata:/data]
volumes:
  uploads:
  pgdata:
  redisdata:
```

## 6. 反向代理

Nginx 关键配置：

```nginx
server {
  listen 443 ssl http2;
  server_name forum.example.com;

  client_max_body_size 25m;

  location / {
    proxy_pass http://app:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 60s;
  }

  location /api/v1/notifications/stream {
    proxy_pass http://app:8080;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 1h;
    proxy_set_header Connection "";
  }

  location /static/ {
    proxy_pass http://app:8080;
    expires 1y;
    add_header Cache-Control "public, immutable";
  }
}
```

- SSE 必须关闭缓冲并延长读超时。
- 上传大小与后端限制一致。
- 只信任来自反代的 `X-Forwarded-*`，配置 `GF_TRUSTED_PROXIES`。
- TLS 1.2+，启用 HSTS；HTTP 301 到 HTTPS。
- 可选 Caddy 自动 HTTPS。

## 7. 目录与权限

```
/                       # 可执行文件（只读）
/data/
  goforum.db            # SQLite（仅 sqlite）
  uploads/              # 本地附件
  backups/              # 本地备份
/config/
  goforum.yaml          # 配置（0600）
/logs/                  # 可选，默认输出 stdout
```

- 运行用户仅对 `/data` 有写权限。
- 上传目录禁止执行；Nginx 不直接暴露目录列表。
- 配置与密钥文件权限 0600，属主为运行用户。

## 8. 备份与恢复

### 8.1 备份内容

| 内容 | 方式 | 频率 |
|---|---|---|
| 数据库 | `pg_dump` / `mysqldump --single-transaction` / `VACUUM INTO` | 每日 |
| 上传文件 | 对象存储版本化或 rsync | 每日 |
| 配置与密钥 | 加密后离线保存 | 变更时 |
| 审计日志 | 数据库导出或归档 | 每月 |

### 8.2 策略

- 本地保留 7 份，异地保留 30 份；加密（age/GPG）。
- RPO ≤ 24h，RTO ≤ 2h（中型社区）。
- 每季度做一次恢复演练，记录耗时与问题。
- 备份文件校验和；恢复前验证完整性。

### 8.3 恢复步骤

1. 停止应用（或进入维护模式）。
2. 恢复数据库到新实例。
3. 恢复上传目录/对象存储。
4. 校验迁移版本与数据量。
5. 启动应用，执行健康检查与冒烟（首页、登录、发帖、支付回调）。
6. 切换流量，观察错误率。

## 9. 监控与日志

### 9.1 健康检查

| 端点 | 用途 |
|---|---|
| `GET /healthz` | 进程存活，返回版本 |
| `GET /readyz` | 数据库、缓存、迁移版本、存储可用性 |
| `GET /metrics` | Prometheus（可选，内网/鉴权） |

### 9.2 指标

- HTTP：QPS、延迟分位、状态码、路由维度。
- 业务：注册、发帖、回复、搜索、支付成功率、回调失败、队列积压。
- 资源：CPU、内存、Goroutine、GC、连接池、磁盘。
- 数据库：慢查询、连接数、复制延迟（如只读副本）。

### 9.3 日志

- 结构化 JSON：`time, level, msg, request_id, user_id, route, status, latency, error`。
- 敏感字段脱敏：密码、Token、密钥、邮箱部分掩码。
- 访问日志与错误日志分离；保留 30 天，审计日志单独保留。
- 错误聚合（Sentry 兼容或自建）：按 fingerprint 分组，附 request_id。

### 9.4 告警

| 告警 | 阈值 |
|---|---|
| 5xx 比例 | > 1%（5 分钟） |
| P95 延迟 | > 500ms（10 分钟） |
| 数据库连接 | > 80% |
| 磁盘 | > 85% |
| 队列积压 | > 1000 或延迟 > 5 分钟 |
| 支付回调失败 | 连续 5 次 |
| 对账差异 | 日终未解释 |
| 证书到期 | < 14 天 |

## 10. 升级与回滚

### 10.1 升级

1. 阅读变更说明与迁移列表。
2. 备份数据库与上传。
3. 进入维护模式（可选；小版本可不停机）。
4. 执行迁移（`./goforum migrate`；先备份）。
5. 替换二进制/镜像，滚动重启。
6. 健康检查 + 冒烟（首页、登录、发帖、支付回调）。
7. 观察 30 分钟错误率与延迟。

### 10.2 兼容规则

- 迁移只加不删；删除分多个版本完成。
- 新旧版本可同时运行（多实例滚动升级）。
- 配置项新增有默认值；删除配置项先停止读取再移除。

### 10.3 回滚

- 二进制回滚：切回上一版本镜像。
- 数据库回滚：优先前向修复；必须回滚时使用备份恢复，并接受数据丢失窗口。
- 回滚后清理缓存版本号，避免旧格式缓存。

## 11. 多实例与扩容

| 组件 | 多实例要求 |
|---|---|
| 应用 | 无状态；会话存数据库；上传走对象存储 |
| 缓存 | Redis 共享；本地缓存仅进程内只读数据 |
| SSE | 每实例独立连接；通知通过数据库轮询或 Redis pub/sub 广播 |
| 定时任务 | 只允许一个实例执行：数据库 advisory lock 或独立 worker |
| 搜索 | 外部引擎共享；数据库全文检索随库 |
| 支付回调 | 任意实例处理，幂等保证正确 |

扩容顺序：数据库读写分离（可选）→ 应用水平扩容 → 对象存储/CDN → 外部搜索。

## 12. 定时任务与队列

- 默认进程内运行（`GF_WORKER_ENABLED=true`）。
- 多实例时设置仅一个实例开启，或使用 `jobs` 表 + advisory lock 选主。
- 任务幂等、可重试、有超时；失败进 `jobs` 并告警。
- 关键任务：关单、补偿查询、退款重试、订阅到期、对账、账本重算、sitemap、索引重建、摘要邮件。

## 13. 故障排查手册

| 现象 | 排查 | 处理 |
|---|---|---|
| 502/504 | 反代到应用连通性、应用是否 OOM | 重启、扩容、查看日志 |
| 数据库连接耗尽 | 连接池、慢查询、泄漏 | 降 `max_open`、杀慢查询、修复泄漏 |
| 磁盘满 | 上传、日志、备份 | 清理孤儿文件、轮转日志、扩容 |
| 队列积压 | worker 是否运行、任务失败 | 重启 worker、重放失败任务 |
| 支付回调失败 | 验签、金额、渠道配置、网络 | 查看 `payment_notify_logs`、补偿查询 |
| SSE 连接暴涨 | 客户端重连风暴、代理超时 | 限流、调整心跳、排查客户端 |
| 搜索无结果 | 索引版本、分词、降级开关 | 重建索引、检查 FTS |
| 页面样式错乱 | 资源 404、CSP 拦截 | 检查 manifest、CSP 报告 |
| 登录失败激增 | 撞库、限流误伤 | 看风控日志、调整阈值、封禁 IP |

## 14. 安全运维

- 操作系统与依赖定期更新；`govulncheck` 纳入 CI。
- 防火墙仅开放 80/443；数据库与 Redis 不暴露公网。
- 最小权限数据库账号（仅所需 DML/DDL）。
- 密钥定期轮换；离职/交接时更换。
- 后台强制 2FA；限制后台 IP（可选）。
- 审计日志异地备份，防止篡改。
- 定期演练备份恢复与支付对账。

## 15. 验收标准

1. 单二进制 + SQLite 可在 5 分钟内启动并完成安装向导。
2. 三种数据库均可完成迁移、启动、冒烟与备份恢复。
3. Docker 镜像非 root、只读根文件系统、健康检查通过。
4. 反代下 SSE 正常、上传大小正确、静态资源长缓存。
5. 备份可恢复，恢复后数据量与关键页面一致。
6. 升级过程可回滚，迁移向后兼容。
7. 多实例部署时定时任务不重复执行、SSE 与缓存正常。
8. 关键告警可触发并送达。
9. 故障手册中的场景均有可执行处理步骤。
10. 审计日志、支付回调日志、账本可支撑事后追溯。
