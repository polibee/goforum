# 13 部署与运维

## 1. 部署形态

| 形态 | 适用 | 依赖 | 说明 |
|---|---|---|---|
| 单二进制 + SQLite | 个人/小社区 | 无 | 零外部依赖，最简单 |
| 单二进制 + MySQL/PG | 中型社区 | 数据库 | 应用与数据库分离 |
| Docker Compose | 标准生产 | DB + 可选 Redis/S3 | 一键启动，便于升级 |
| 多实例 | 大型社区 | DB + Redis + 对象存储 | 无状态应用 + 共享存储 |

约束：**SQLite 只允许单实例**；多实例必须使用 MySQL/PostgreSQL + 共享 Redis（缓存/广播）+ 对象存储。

## 2. 构建

```bash
npm ci
npm run build            # Tailwind + esbuild → web/static/dist
make build               # CGO_ENABLED=0，产物 bin/goforum
```

等价的底层命令：

```bash
CGO_ENABLED=0 go build -trimpath \
  -ldflags "-s -w -X main.version=$(git describe --tags --always)" \
  -o bin/goforum ./cmd/goforum
```

- `CGO_ENABLED=0`：SQLite 使用纯 Go 驱动（`glebarez/sqlite`），便于交叉编译与 Alpine 镜像。
- 模板、静态资源与语言文件通过 `embed.FS` 内嵌；`go build` 前必须先执行 `npm run build`，否则缺少 `web/static/dist`。
- 版本号注入 `main.version`，`/healthz` 与后台“关于”展示。
- 一键部署脚本会自动完成上述构建：裸机 `scripts/deploy.sh`，Docker `scripts/docker-deploy.sh`，详见 [34 一键部署脚本与 Docker](./34-一键部署脚本与Docker.md)。

## 3. 配置

配置优先级（后者覆盖前者）：

```text
内置默认值 → configs/goforum.yaml → .env → 真实环境变量
```

推荐把基础设施配置写入 `.env`（Laravel 风格）；`.env` 路径由 `GF_ENV_FILE` 指定，默认 `./.env`。即使没有 `.env` 文件，进程环境中的 `APP_*` / `DB_*` 也会生效。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `APP_ENV` | `production` | production/development；production 不执行 AutoMigrate |
| `APP_URL` | — | 站点公开 URL，生产必须是 `https://` |
| `APP_KEY` | — | AES-256-GCM 主密钥（32 字节 base64） |
| `HTTP_ADDR` | `:8080` | 监听地址 |
| `HTTP_MAX_BODY_MB` | `32` | 单次请求体上限 |
| `HTTP_TRUSTED_PROXIES` | — | 反代 CIDR，逗号分隔 |
| `HTTP_METRICS_ENABLED` / `HTTP_METRICS_TOKEN` | `false` / — | Prometheus 指标与 Bearer 鉴权 |
| `DB_CONNECTION` | `sqlite` | `sqlite` / `mysql` / `pgsql` |
| `DB_DSN` | `./data/goforum.db` | 完整连接串，优先于分项字段 |
| `DB_HOST` / `DB_PORT` / `DB_DATABASE` / `DB_USERNAME` / `DB_PASSWORD` / `DB_SSLMODE` | — | 分项数据库配置 |
| `DB_MAX_OPEN` / `DB_MAX_IDLE` / `DB_MAX_LIFETIME` | `25` / `10` / `30m` | 连接池 |
| `CACHE_STORE` | `memory` | `memory` / `redis` |
| `REDIS_URL` | — | Redis 连接串 |
| `FILESYSTEM_DISK` | `local` | 当前仅本地存储 |
| `STORAGE_PATH` | `./data/uploads` | 上传目录 |
| `MAIL_MAILER` | `log` | `log` / `smtp` |
| `MAIL_HOST` / `MAIL_PORT` / `MAIL_USERNAME` / `MAIL_PASSWORD` / `MAIL_FROM_ADDRESS` | — | 邮件 |
| `LOG_LEVEL` / `LOG_CHANNEL` | `info` / `json` | 日志 |
| `SESSION_COOKIE` / `SESSION_LIFETIME` | `gf_session` / `720h` | 会话 |
| `WORKER_ENABLED` | `true` | 进程内后台任务 |
| `GF_BACKUP_KEY` | — | 备份加密密钥，只从进程环境读取 |
| `GF_CONFIG` | `configs/goforum.yaml` | YAML 配置路径 |
| `GF_ENV_FILE` | `./.env` | `.env` 路径 |

`GF_*`（如 `GF_DB_DSN`、`GF_SECRET_KEY`、`GF_LOG_LEVEL`）是旧版直连环境变量，仍然兼容；新部署统一使用上表。

数据库切换：在安装向导中选择，或在 `.env` 中配置 `DB_CONNECTION` 与 `DB_DSN`。安装向导会把选择追加到 `.env` 末尾，保证重启后仍指向同一个库。

敏感设置（SMTP、支付、OAuth 密钥）落库前使用 `APP_KEY` 做 AES-256-GCM 加密。**不要更换或丢失 `APP_KEY`**，否则已加密设置与管理员 TOTP 无法解密。

## 4. 三种数据库部署

### 4.1 SQLite

- 驱动：纯 Go（`glebarez/sqlite`），无需 CGO。
- DSN 参数：`?_pragma=journal_mode(WAL)&_pragma=busy_timeout(5000)&_pragma=foreign_keys(1)&_pragma=synchronous(NORMAL)`
- 文件放在本地 SSD，**禁止网络文件系统**（NFS/SMB 会导致锁异常）。
- 单写者：写事务保持短小；高并发写场景改用 MySQL/PG。
- 备份：`VACUUM INTO 'backup.db'` 或 `sqlite3 .backup`，不要直接复制正在写入的文件。
- 上限建议：≤ 20 万主题、≤ 50 万用户；超过后迁移。

### 4.2 MySQL

- 版本 8.0+；`utf8mb4` + `utf8mb4_0900_ai_ci`；InnoDB。
- DSN：`user:pass@tcp(db:3306)/goforum?charset=utf8mb4&parseTime=True&loc=UTC&multiStatements=false`
- `max_connections` ≥ 应用连接池总和的 1.5 倍；慢查询日志开启。
- 全文检索使用 ngram parser（`ngram_token_size=2`），需在初始化时创建 FULLTEXT 索引。
- 大表变更使用在线 DDL（`ALGORITHM=INPLACE`）或 gh-ost（超大规模）。

### 4.3 PostgreSQL

- 版本 14+；UTF8；`TimeZone=UTC`。
- DSN：`host=db user=goforum password=*** dbname=goforum sslmode=require TimeZone=UTC`
- JSONB、GIN、tsvector 原生支持；中文分词可用 `zhparser`（可选）。
- 连接池：应用侧 `max_open` 控制；PgBouncer 使用 transaction 模式时注意 prepared statements。
- 自动 vacuum 监控；大表写入关注膨胀。

### 4.4 数据库迁移

- 生产启动不执行 `AutoMigrate`；启动前用 `EnsureSchema` 校验表和列，并校验 `schema_migrations` 台账，缺失则拒绝启动。
- 当前迁移命令为 `./goforum migrate`：按版本顺序执行未应用迁移，写入 `schema_migrations`，随后再次校验 schema。
- 已注册迁移：`0001 baseline_models`（当前模型基线）、`0002 legacy_subscriptions`（历史订阅拆分）。
- 迁移前必须先备份；生产升级建议停应用或进入维护模式后执行。
- 新迁移追加到 `internal/app/schema.go` 的 `schemaMigrations`，版本号递增；不要修改已发布迁移。
- 多实例：迁移由单独 Job/首实例执行；当前尚未实现数据库 advisory lock，需人工保证同一时间只有一个实例执行。

## 5. Docker

仓库提供三份文件：

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 三段构建：Node 资源 → Go 二进制 → Alpine 运行镜像 |
| `docker-compose.yml` | 单服务 + 命名卷 `goforum-data` + 健康检查 |
| `scripts/docker-deploy.sh` | 生成密钥、构建、启动、等待健康检查 |

一键启动：

```bash
./scripts/docker-deploy.sh
# 或指定公开地址与端口
./scripts/docker-deploy.sh --url https://forum.example.com --port 8080
```

首次运行生成 `goforum.env`（0600）：`APP_KEY`、`GF_BACKUP_KEY`、监听地址、日志与会话配置。数据、上传、安装向导写入的 `goforum.yaml` 与备份都在命名卷 `goforum-data` 中。

镜像特征：

- `node:22-alpine` 构建 Tailwind/esbuild；`golang:1.27-alpine` 以 `CGO_ENABLED=0` 编译；`alpine:3.22` 运行。
- 运行用户为 `goforum`（UID 10001），入口脚本仅修正 `/data` 属主后 `su-exec` 降权。
- 健康检查使用 BusyBox `wget` 请求 `/healthz`；无需额外安装 curl。
- 模板、静态资源、语言文件全部内嵌，镜像只包含一个二进制。

Compose 关键配置：

```yaml
services:
  goforum:
    build:
      context: .
      args:
        VERSION: ${GOFORUM_VERSION:-dev}
    env_file: [./goforum.env]
    environment:
      GF_ENV_FILE: /data/.env
      GF_CONFIG: /data/goforum.yaml
    ports: ["${GOFORUM_PORT:-8080}:8080"]
    volumes: [goforum-data:/data]
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:8080/healthz"]
volumes:
  goforum-data:
```

容器工作目录为 `/`，默认 SQLite 路径 `./data/goforum.db` 即 `/data/goforum.db`；备份默认写入 `/backups`（符号链接到 `/data/backups`）。安装向导选择的数据库写入 `/data/goforum.yaml` 并随卷持久化。

### 5.1 Docker 运维

```bash
docker compose logs -f goforum
docker compose restart goforum
docker compose exec goforum /app/goforum backup
docker compose exec goforum /app/goforum migrate
docker compose down          # 保留数据卷
docker compose down -v       # 删除数据卷（不可恢复）
```

升级：

```bash
git pull
./scripts/docker-deploy.sh
```

生产环境建议把端口改为 `127.0.0.1:8080:8080` 并只暴露 443 给反向代理。完整参数、外部数据库与故障排查见 [34 一键部署脚本与 Docker](./34-一键部署脚本与Docker.md)。

## 6. 反向代理

Nginx 关键配置：

```nginx
server {
  listen 443 ssl http2;
  server_name forum.example.com;

  client_max_body_size 32m;

  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 60s;
  }

  location /api/v1/notifications/stream {
    proxy_pass http://127.0.0.1:8080;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 1h;
    proxy_set_header Connection "";
  }

  location /static/ {
    proxy_pass http://127.0.0.1:8080;
    expires 1y;
    add_header Cache-Control "public, immutable";
  }
}
```

- SSE 必须关闭缓冲并延长读超时。
- 上传大小与后端限制一致。
- 只信任来自反代的 `X-Forwarded-*`，配置 `HTTP_TRUSTED_PROXIES`（Docker 网络按反代容器网段填写）。
- TLS 1.2+，启用 HSTS；HTTP 301 到 HTTPS。
- 可选 Caddy 自动 HTTPS。

## 7. 目录与权限

裸机（`scripts/deploy.sh`）：

```
/opt/goforum/
  goforum              # 可执行文件（root:root 0755）
  .env                 # APP_KEY / GF_BACKUP_KEY / 监听配置（0600）
  configs/goforum.yaml # 安装向导写入（0600）
  data/goforum.db      # SQLite（仅 sqlite）
  data/uploads/        # 本地附件
  backups/             # 本地备份
```

Docker（命名卷 `goforum-data`）：

```
/data/
  goforum.db           # SQLite
  goforum.yaml         # 安装向导写入
  uploads/             # 附件
  backups/             # 备份（容器内 /backups 指向这里）
```

- 裸机运行用户为 `goforum`，仅对 `data/`、`backups/`、`configs/` 有写权限；`ProtectSystem=strict`。
- Docker 运行用户为 UID 10001；入口脚本只修正卷目录属主后降权。
- 上传目录禁止执行；Nginx 不直接暴露目录列表。
- 配置与密钥文件权限 0600，属主为运行用户；`.env` 不要提交到 Git。

## 8. 备份与恢复

### 8.1 备份内容

| 内容 | 方式 | 频率 |
|---|---|---|
| 数据库 | `pg_dump` / `mysqldump --single-transaction` / `VACUUM INTO` | 每日 |
| 上传文件 | 对象存储版本化或 rsync | 每日 |
| 配置与密钥 | 加密后离线保存 | 变更时 |
| 审计日志 | 数据库导出或归档 | 每月 |

### 8.2 策略

- 本地保留 7 份，异地保留 30 份；加密（age/GPG）。
- RPO ≤ 24h，RTO ≤ 2h（中型社区）。
- 每季度做一次恢复演练，记录耗时与问题。
- 备份文件校验和；恢复前验证完整性。

### 8.3 恢复步骤

1. 停止应用（或进入维护模式）。
2. 恢复数据库到新实例。
3. 恢复上传目录/对象存储。
4. 校验迁移版本与数据量。
5. 启动应用，执行健康检查与冒烟（首页、登录、发帖、支付回调）。
6. 切换流量，观察错误率。

## 9. 监控与日志

### 9.1 健康检查

| 端点 | 用途 |
|---|---|
| `GET /healthz` | 进程存活，返回版本 |
| `GET /readyz` | 数据库、缓存、迁移版本、存储可用性 |
| `GET /metrics` | Prometheus（可选，内网/鉴权） |

### 9.2 指标

- HTTP：QPS、延迟分位、状态码、路由维度。
- 业务：注册、发帖、回复、搜索、支付成功率、回调失败、队列积压。
- 资源：CPU、内存、Goroutine、GC、连接池、磁盘。
- 数据库：慢查询、连接数、复制延迟（如只读副本）。

### 9.3 日志

- 结构化 JSON：`time, level, msg, request_id, user_id, route, status, latency, error`。
- 敏感字段脱敏：密码、Token、密钥、邮箱部分掩码。
- 访问日志与错误日志分离；保留 30 天，审计日志单独保留。
- 错误聚合（Sentry 兼容或自建）：按 fingerprint 分组，附 request_id。

### 9.4 告警

| 告警 | 阈值 |
|---|---|
| 5xx 比例 | > 1%（5 分钟） |
| P95 延迟 | > 500ms（10 分钟） |
| 数据库连接 | > 80% |
| 磁盘 | > 85% |
| 队列积压 | > 1000 或延迟 > 5 分钟 |
| 支付回调失败 | 连续 5 次 |
| 对账差异 | 日终未解释 |
| 证书到期 | < 14 天 |

## 10. 升级与回滚

### 10.1 升级

1. 阅读变更说明与迁移列表。
2. 备份数据库与上传。
3. 进入维护模式（可选；小版本可不停机）。
4. 执行迁移（`./goforum migrate`；先备份）。
5. 替换二进制/镜像，滚动重启。
6. 健康检查 + 冒烟（首页、登录、发帖、支付回调）。
7. 观察 30 分钟错误率与延迟。

一键部署方式的升级：

```bash
# 裸机
git pull
sudo ./scripts/deploy.sh --upgrade

# Docker
git pull
./scripts/docker-deploy.sh
docker compose exec goforum /app/goforum migrate
```

### 10.2 兼容规则

- 迁移只加不删；删除分多个版本完成。
- 新旧版本可同时运行（多实例滚动升级）。
- 配置项新增有默认值；删除配置项先停止读取再移除。

### 10.3 回滚

- 二进制回滚：切回上一版本镜像。
- 数据库回滚：优先前向修复；必须回滚时使用备份恢复，并接受数据丢失窗口。
- 回滚后清理缓存版本号，避免旧格式缓存。

## 11. 多实例与扩容

| 组件 | 多实例要求 |
|---|---|
| 应用 | 无状态；会话存数据库；上传走对象存储 |
| 缓存 | Redis 共享；本地缓存仅进程内只读数据 |
| SSE | 每实例独立连接；通知通过数据库轮询或 Redis pub/sub 广播 |
| 定时任务 | 只允许一个实例执行：数据库 advisory lock 或独立 worker |
| 搜索 | 外部引擎共享；数据库全文检索随库 |
| 支付回调 | 任意实例处理，幂等保证正确 |

扩容顺序：数据库读写分离（可选）→ 应用水平扩容 → 对象存储/CDN → 外部搜索。

## 12. 定时任务与队列

- 默认进程内运行（`WORKER_ENABLED=true`）。
- 多实例时设置仅一个实例开启，或使用 `jobs` 表 + advisory lock 选主。
- 任务幂等、可重试、有超时；失败进 `jobs` 并告警。
- 关键任务：关单、补偿查询、退款重试、订阅到期、对账、账本重算、sitemap、索引重建、摘要邮件。

## 13. 故障排查手册

| 现象 | 排查 | 处理 |
|---|---|---|
| 502/504 | 反代到应用连通性、应用是否 OOM | 重启、扩容、查看日志 |
| 数据库连接耗尽 | 连接池、慢查询、泄漏 | 降 `max_open`、杀慢查询、修复泄漏 |
| 磁盘满 | 上传、日志、备份 | 清理孤儿文件、轮转日志、扩容 |
| 队列积压 | worker 是否运行、任务失败 | 重启 worker、重放失败任务 |
| 支付回调失败 | 验签、金额、渠道配置、网络 | 查看 `payment_notify_logs`、补偿查询 |
| SSE 连接暴涨 | 客户端重连风暴、代理超时 | 限流、调整心跳、排查客户端 |
| 搜索无结果 | 索引版本、分词、降级开关 | 重建索引、检查 FTS |
| 页面样式错乱 | 资源 404、CSP 拦截 | 检查 manifest、CSP 报告 |
| 登录失败激增 | 撞库、限流误伤 | 看风控日志、调整阈值、封禁 IP |

## 14. 安全运维

- 操作系统与依赖定期更新；`govulncheck` 纳入 CI。
- 防火墙仅开放 80/443；数据库与 Redis 不暴露公网。
- 最小权限数据库账号（仅所需 DML/DDL）。
- 密钥定期轮换；离职/交接时更换。
- 后台强制 2FA；限制后台 IP（可选）。
- 审计日志异地备份，防止篡改。
- 定期演练备份恢复与支付对账。

## 15. 验收标准

1. 单二进制 + SQLite 可在 5 分钟内启动并完成安装向导。
2. 三种数据库均可完成迁移、启动、冒烟与备份恢复。
3. Docker 镜像非 root、只读根文件系统、健康检查通过。
4. 反代下 SSE 正常、上传大小正确、静态资源长缓存。
5. 备份可恢复，恢复后数据量与关键页面一致。
6. 升级过程可回滚，迁移向后兼容。
7. 多实例部署时定时任务不重复执行、SSE 与缓存正常。
8. 关键告警可触发并送达。
9. 故障手册中的场景均有可执行处理步骤。
10. 审计日志、支付回调日志、账本可支撑事后追溯。
