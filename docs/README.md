# GoForum 设计与开发文档

> 用 **Go + Gin + Go html/template + Alpine.js 3 + Tailwind CSS + Pines** 构建的模块化社区论坛。
> 当前阶段：**M0–M7 与生产加固已落地**；实现说明见 15–33。
>
> 产品文档：[中文](./product/zh-CN/README.md) · [English](./product/en-US/README.md)
> AI 开发文档：[中文](./product/zh-CN/AI-DEVELOPMENT.md) · [English](./product/en-US/AI-DEVELOPMENT.md)

## 1. 一句话定位

GoForum 是一个**可自托管、单二进制部署、支持 SQLite / MySQL / PostgreSQL 自选数据库**的通用社区论坛：以 Discourse 的内容组织与治理能力为内核，融合 NodeSeek 的积分、等级、邀请、抽奖等运营玩法，并通过模块化设计与可插拔支付渠道支持长期演进。

## 2. 技术栈

| 层次 | 选型 | 说明 |
|---|---|---|
| 语言 | Go 1.27+ | 单二进制、`embed.FS` 内嵌模板与静态资源 |
| Web 框架 | Gin v1 | 路由、中间件、分组 |
| 模板 | Go `html/template` | 服务端渲染，布局 + 局部模板 |
| 交互 | Alpine.js 3 | 局部状态、下拉、弹层、轮询、乐观更新 |
| UI 组件 | Pines（DevDojo） | Alpine + Tailwind 的复制粘贴式组件库，本地化后使用 |
| 样式 | Tailwind CSS | 设计 token + 组件层，CLI 构建 |
| ORM | GORM v2 | 模型、关联、软删除、迁移辅助 |
| 数据库 | SQLite / MySQL / PostgreSQL | 安装向导或配置文件选择 |
| 缓存/队列/存储/搜索/邮件 | 可插拔 | 默认内存 + 本地磁盘 + 进程内队列，可选 Redis / S3 / 外部搜索 |
| 支付 | 渠道注册表 | 一期余额、人工、支付宝、微信；二期 Stripe、PayPal |

## 5. 术语表

| 中文 | 英文 / 代码标识 | 定义 |
|---|---|---|
| 主题 | topic | 一个讨论帖，包含标题、板块、标签和若干回复 |
| 回复 | post | 主题下的单条内容，拥有楼层号 |
| 板块 | category | 内容的一级/多级分类，决定权限与展示位置 |
| 标签 | tag | 跨板块的内容标记，可分组、可设同义词 |
| 用户组 | group | 权限集合，用户可属于多个组 |
| 信任等级 | trust level (TL) | TL0–TL4，基于活跃度自动晋升的行为权限层 |
| 阅读状态 | read state | 用户在某主题中读到的楼层与未读数 |
| 通知级别 | notification level | 关注 / 追踪 / 普通 / 静音 |
| 举报 | flag | 用户对内容或账号的违规报告 |
| 审核队列 | review queue | 待人工处理的审核项集合 |
| 积分 | points | 站内虚拟积分，可赚取与消费，不可提现 |
| 余额 | balance | 通过真实支付充值的站内货币，用于购买 |
| 权益 | entitlement | 用户对某资源（主题、附件、板块、用户组）的访问授权 |
| 账本 | ledger | 复式记账的余额与积分流水，可审计、可重算 |
| 托管 | escrow | 悬赏/担保场景下先冻结、后结算的资金 |
| 支付渠道 | payment channel | 一个具体支付实现（余额、人工、支付宝、微信等） |
| 站点设置 | site setting | 由后台维护的 `namespace.key` 配置项 |
| 站点设计 | site design | 品牌、主题、布局、导航、页面等站点级外观配置 |
| 模块 | module | 垂直切片的功能单元，拥有自己的表、路由、权限、后台贡献 |

## 6. 架构决策记录（ADR 摘要）

| 编号 | 决策 | 理由 | 影响 |
|---|---|---|---|
| ADR-001 | 采用模块化单体，不拆微服务、不用 Go 多 module | 单二进制部署、开发效率高；通过契约与事件保持可拆分性 | 需要 CI 强制模块边界 |
| ADR-002 | 服务端渲染为主，Alpine 负责局部交互 | SEO 友好、首屏快、无 SPA 复杂度；表单无 JS 可用 | 局部数据走 JSON 接口 |
| ADR-003 | 主键统一 ULID（char(26)） | 规避三数据库自增差异，按时间有序，URL 稳定 | 索引体积略增 |
| ADR-004 | 多数据库通过方言能力层隔离 | 一套业务代码支持三种数据库 | 检索/锁/Upsert 需按方言实现 |
| ADR-005 | 缓存、存储、队列、邮件、搜索全部接口化 | 默认零外部依赖，生产按需替换 | 每个接口需内存/本地默认实现 |
| ADR-006 | 支付渠道使用注册表 + 配置 schema | 新增渠道不改订单与账本核心 | 每渠道需实现统一接口与回调 |
| ADR-007 | 站点外观与行为由设置驱动 | 同一份代码服务不同社区，后台可改 | 禁止硬编码站点名、颜色、导航 |
| ADR-008 | SEO 以服务端渲染 + 明确索引矩阵为基础 | 论坛核心流量来自搜索 | 每个页面类型必须声明 index/noindex |
| ADR-009 | 私信为独立模块，不复用主题表 | 权限与展示差异大，边界更清晰 | 复用 Markdown、上传、通知能力 |
| ADR-010 | 金额统一用 int64 最小货币单位 | 避免浮点误差，跨渠道一致 | 展示层负责格式化 |

## 7. 文档约定

- **规范性用语**：必须（MUST）、应当（SHOULD）、可以（MAY）遵循 RFC 2119 语义。
- **优先级**：P0 首个可上线版本必须；P1 上线后一个迭代内；P2 后续增强。
- **ID**：所有业务实体使用 ULID（26 位 Crockford Base32）；对外 URL 使用 `id + slug`。
- **时间**：数据库存 UTC；展示按用户时区；接口使用 RFC 3339。
- **金额**：`amount_minor`（int64）+ `currency`（ISO 4217），禁止浮点。
- **命名**：表名小写复数蛇形（`topic_users`）；Go 包小写单词；权限键 `domain.action`。
- **数据库**：不使用外键级联删除，采用应用层约束 + 软删除；计数字段允许冗余但必须可重算。
- **文档即契约**：实现与文档不一致时，先改文档再改代码。
