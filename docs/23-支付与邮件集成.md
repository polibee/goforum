# 支付与邮件集成说明

本批增量在 M5 订单/账本体系上接入 NOWPayments、XCash、Deipay 等加密货币支付渠道，并把邮件从日志输出扩展为 SMTP / Resend。

## 1. 支付渠道注册

`billing.EnsureDefaults` 现在按驱动幂等补齐渠道，已有渠道不会被覆盖：

| 驱动 | 名称 | 默认状态 | 模式 |
| --- | --- | --- | --- |
| `balance` | 站内余额 | 启用 | live |
| `manual` | 人工确认 | 启用 | live |
| `alipay` | 支付宝（沙箱） | 启用 | sandbox |
| `wechat` | 微信支付（沙箱） | 启用 | sandbox |
| `nowpayments` | NOWPayments | 停用 | live |
| `xcash` | XCash | 停用 | live |
| `deipay` | Deipay | 停用 | live |
| `creem` | Creem | 停用 | live |
| `lemonsqueezy` | Lemon Squeezy | 停用 | live |

使用前在 `/admin/billing` 启用对应渠道；配置缺失时创建订单会返回明确错误，不会生成不可支付的订单。

## 2. NOWPayments

### 配置

后台「站点设置 → 支付」或环境变量：

| 设置键 | 说明 |
| --- | --- |
| `billing.nowpayments.api_key` | API Key，请求头 `x-api-key` |
| `billing.nowpayments.ipn_secret` | IPN HMAC 密钥 |
| `billing.nowpayments.base_url` | 默认 `https://api.nowpayments.io/v1` |
| `billing.nowpayments.pay_currency` | 可选，留空让用户在托管页选择币种 |

前置条件：`site.general.url` 必须配置为公网可访问地址，用于生成 `ipn_callback_url`。

### 下单

`POST /invoice` 请求体：

```json
{
  "price_amount": 19.99,
  "price_currency": "usd",
  "order_id": "GF2026...",
  "order_description": "VIP 30 天",
  "ipn_callback_url": "https://forum.example.com/payments/nowpayments/notify",
  "success_url": "https://forum.example.com/checkout/GF...?paid=1",
  "cancel_url": "https://forum.example.com/checkout/GF..."
}
```

返回的 `invoice_url` 写入订单 `pay_url`，收银台展示“前往支付”并新窗口打开。

### 回调

`POST /payments/nowpayments/notify`

1. 读取原始 JSON，使用 `UseNumber` 保留数字字面量；
2. 重新序列化（对象键排序）得到签名原文；
3. `HMAC-SHA512(ipn_secret, canonicalJSON)` 与 `x-nowpayments-sig` 常量时间比较；
4. 校验订单存在、渠道一致、`price_amount` 与订单金额一致；
5. `payment_status` 为 `finished` / `confirmed` 时调用 `PayOrder`，状态机与账本幂等；
6. `expired` / `failed` 关闭待支付订单；
7. 处理成功返回 `200 ok`，验签或金额失败返回 400。

该回调在 CSRF 中间件中按路径豁免，安全性由 HMAC 签名保证。

## 3. XCash

### 配置

后台「站点设置 → 支付」的 XCash 表单，或在环境变量中配置：

| 设置键 | 说明 |
| --- | --- |
| `billing.xcash.appid` | 项目 AppID，形如 `XC-XXXXXXXX` |
| `billing.xcash.hmac_key` | HMAC 密钥（Secret，加密存储） |
| `billing.xcash.base_url` | API 网关，默认 `https://pay.xca.sh` |
| `billing.xcash.duration` | 账单有效期分钟数，5–30，默认 15 |

`billing.xcash.appid` 字段旁提供「前往注册」按钮（推广链接）。前置条件：`site.general.url` 必须是公网 HTTPS 地址，用于生成 `notify_url` 与 `return_url`。

### 创建账单

`POST {base_url}/v1/invoice`，请求头：

```text
XC-Appid: {appid}
XC-Timestamp: {unix_timestamp}
XC-Nonce: {random_nonce}
XC-Signature: HMAC-SHA256(nonce + timestamp + body, hmac_key).hexdigest()
Content-Type: application/json
```

请求体：

```json
{
  "out_no": "ORDER...",
  "title": "商品名称（最长 32 字符）",
  "currency": "USD",
  "amount": "29.99",
  "duration": 15,
  "notify_url": "https://forum.example.com/payments/xcash/notify",
  "return_url": "https://forum.example.com/checkout/ORDER...?paid=1"
}
```

成功响应返回 `pay_url`，收银台跳转该地址完成选链、选币与付款。

### 回调

`POST /payments/xcash/notify`：

- 校验 `XC-Appid`、`XC-Timestamp`（±300 秒）、`XC-Nonce`、`XC-Signature`。
- 只处理 `type=invoice` 且 `confirmed=true` 的事件；`deposit` 等其他事件返回 `ok` 但不影响订单。
- 订单状态与账本写入保持幂等；成功响应必须为纯文本 `ok`。
- 金额以订单法币金额为准，回调中的 `pay_amount` 是加密货币数量，不用于金额比对。

### 边界

- 自动退款未接入；后台退款仍按站内余额入账，XCash 侧需人工退款。
- 收款链/币由 XCash 项目后台配置决定，本集成不传 `methods`。
- 测试项目只能使用 XCash 测试网/本地链；生产使用主网配置。

## 4. Deipay

### 配置

| 设置键 | 说明 |
| --- | --- |
| `billing.deipay.session_key` | secp256k1 私钥（32 字节十六进制，可带 `0x`） |
| `billing.deipay.base_url` | 默认 `https://api.depipay.com` |
| `billing.deipay.chain_id` | 默认 `1`（Ethereum） |
| `billing.deipay.tokens` | 接收代币白名单，逗号分隔，如 `1:0xdac1...` |
| `billing.deipay.deadline_secs` | 发票有效期，默认 86400 秒 |

### 签名

每次请求生成毫秒时间戳 `nonce`，签名原文：

```
sess:{nonce}:{sha256(body) 的小写十六进制}
```

按 EIP-191 `personal_sign` 计算 keccak256 摘要，使用 secp256k1 签名，输出 `r||s||v`（65 字节，v 为 27/28），放入：

```
x-session-nonce
x-session-signature
x-encryption: none
```

### 下单与状态同步

- `POST /invoice` 返回 `paymentUrl` 并写入订单 `pay_url`。
- 发票 `data.order_no` 保存本站订单号。
- Deipay 不提供 webhook，应用每 5 秒调用 `POST /poll/events` 拉取状态变更：
  - 仅在渠道启用且配置了 Session Key 时轮询；
  - `paid` 事件按订单号完成支付；
  - `expired` 关闭待支付订单；
  - 事件由 Deipay 侧消费，轮询失败只记录日志，不阻塞其他任务。

金额口径：订单金额（分）除以 100 后作为 Deipay 的 USD `value` 字符串。**当前按 1:1 处理，不做汇率换算**，因此使用 Deipay 时应把商品价格视为美元定价，或在运营层面自行换算。

## 5. Creem 与 Lemon Squeezy

两者都是 Merchant of Record，使用托管结账页，本站只保存订单与支付结果。

### 配置

| 设置键 | 说明 |
| --- | --- |
| `billing.creem.api_key` | Creem API Key（`x-api-key`） |
| `billing.creem.webhook_secret` | Creem Webhook 签名密钥 |
| `billing.creem.base_url` | 默认 `https://api.creem.io/v1` |
| `billing.creem.products` | JSON 映射：本站商品 slug → Creem `product_id` |
| `billing.lemonsqueezy.api_key` | Lemon Squeezy API Key（Bearer） |
| `billing.lemonsqueezy.webhook_secret` | Webhook 签名密钥 |
| `billing.lemonsqueezy.base_url` | 默认 `https://api.lemonsqueezy.com/v1` |
| `billing.lemonsqueezy.store_id` | Store ID |
| `billing.lemonsqueezy.variants` | JSON 映射：本站商品 slug → Variant ID |

示例：

```json
{"vip-30": "prod_xxxxx"}
```

```json
{"vip-30": "123456"}
```

商品 slug 在下单时写入订单快照（`orders.product_slug`），因此修改商品 slug 后旧订单仍按原映射处理。

### 下单

- Creem：`POST /checkouts`，请求体包含 `product_id`、`request_id`（本站订单号）、`success_url`；返回 `checkout_url`。
- Lemon Squeezy：`POST /checkouts`（JSON:API），通过 `checkout_data.custom.order_no` 携带本站订单号，`product_options.redirect_url` 指向收银台；返回 `data.attributes.url`。

两者返回的 URL 都写入订单 `pay_url`，收银台新窗口打开。

### 回调

| 渠道 | 路径 | 验签 |
| --- | --- | --- |
| Creem | `/payments/creem/notify` | `creem-signature` = HMAC-SHA256(raw body, webhook_secret) |
| Lemon Squeezy | `/payments/lemonsqueezy/notify` | `X-Signature` = HMAC-SHA256(raw body, webhook_secret) |

处理逻辑复用统一入口 `HandleNotify`：

- 校验签名、订单号、渠道与金额；
- Creem 从 `object.request_id` 取订单号，`object.order.status` 为 `paid` 时完成支付；
- Lemon Squeezy 从 `meta.custom_data.order_no` 取订单号，`data.attributes.status` 为 `paid` 时完成支付；
- 重复回调幂等，失败返回 400 让渠道重试。

两个回调路径均在 CSRF 中间件中豁免，安全性由签名保证。

### 退款

尚未调用两家的退款 API；后台退款仍按站内余额入账，渠道侧需人工发起退款。

## 6. 邮件

### 配置

后台「站点设置 → 通知与邮件」：

| 设置键 | 说明 |
| --- | --- |
| `mail.provider` | `log` / `smtp` / `resend` |
| `mail.from` | 发件人，如 `GoForum <no-reply@example.com>` |
| `mail.smtp.host` / `port` / `username` / `password` | SMTP 参数 |
| `mail.resend.api_key` | Resend API Key |
| `mail.resend.base_url` | 默认 `https://api.resend.com` |

兼容原有 `configs/goforum.yaml` 的 `mail.*` 配置：未在后台设置 provider 时，`mail.enabled=true` 自动使用 SMTP；`RESEND_API_KEY` 可作为 Resend Key 的兜底。

### 行为

- `log`：只记录日志，不发送（开发默认）。
- `smtp`：587 端口使用 STARTTLS；465 端口使用隐式 TLS；支持用户名密码认证。
- `resend`：`POST /emails`，Bearer 鉴权，JSON 包含 `from/to/subject/html/text`；纯文本会自动生成简单 HTML。
- 邮件在每次发送时解析 provider，后台切换后无需重启。
- 当前接入点为注册验证、找回密码等认证邮件；发送失败由调用方记录，不阻断注册流程。

## 7. 数据库与兼容性

- `orders` 新增 `pay_url`，AutoMigrate 自动添加，旧订单为空时收银台回退到沙箱/人工逻辑。
- `payment_channels` 新增 NOWPayments/Deipay 两条记录，已有安装启动时自动补齐。
- Deipay 依赖 `github.com/decred/dcrd/dcrec/secp256k1/v4` 与 `golang.org/x/crypto/sha3`（EIP-191）。

## 8. 后台操作

1. `/admin/settings` 填入支付/邮件配置，保存后即时生效。
2. `/admin/billing` 启用 `NOWPayments`、`XCash`、`Deipay` 渠道。
3. 前台 `/pricing` 选择渠道下单。
4. NOWPayments / XCash 在托管页完成支付后等待 IPN；Deipay 在托管页完成后 5 秒内由轮询更新。
5. `/billing/orders` 与 `/billing/subscription` 查看结果。

## 10. 当前边界

- NOWPayments / XCash / Deipay 退款未调用渠道 API：后台退款仍按站内余额入账，渠道侧需人工处理。
- Deipay 轮询为单进程内定时任务；多实例部署会重复拉取，建议只在一个实例启用或改为分布式锁。
- Deipay 金额不做汇率换算。
- 邮件为同步发送，未接入队列与重试；大规模通知应改为异步队列。
- Creem / Lemon Squeezy 退款未调用渠道 API，需人工处理。
