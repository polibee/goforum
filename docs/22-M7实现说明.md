# M7 实现说明：硬化、监控与备份

M7 聚焦上线前的稳定性与可运维性：请求限流、请求体上限、Prometheus 指标、统一备份命令、压测脚本，以及一次真实的升级迁移修复。

## 1. 交付范围

| 能力 | 实现 |
| --- | --- |
| 限流 | 进程内固定窗口限流，按 IP + 桶名隔离 |
| 请求体上限 | 全局 `http.max_body_bytes`，默认 32 MiB |
| 指标 | `/metrics` Prometheus 文本格式，可选 Bearer Token |
| 健康检查 | `/healthz`（存活）、`/readyz`（数据库 Ping） |
| 备份 | `goforum backup`：数据库 + 上传目录 + SHA256 清单 |
| 压测 | `scripts/loadtest.js`（k6），覆盖首页/主题/搜索/定价/Feed/Sitemap |
| 升级修复 | 拆分同名 `subscriptions` 表，迁移关注与订阅数据 |
| 配置 | 新增 HTTP 配置项与环境变量 |

## 2. 限流

实现：`internal/platform/middleware/ratelimit.go`

- 固定窗口计数，键为 `ClientIP|bucket`，到期自动重置。
- 每 1024 次请求清理一次过期桶，避免无限增长。
- 超限返回 `429`，带 `Retry-After`；HTML 页面渲染错误页，JSON 请求返回 `rate_limited`。
- IP 解析遵循 Gin 的 `SetTrustedProxies`：仅在配置可信代理时读取 `X-Forwarded-For`。

| 路由 | 桶 | 限制 |
| --- | --- | --- |
| `POST /login` | `login` | 10 次 / 5 分钟 |
| `POST /register` | `register` | 5 次 / 小时 |
| `POST /verify-email/resend` | `verify_resend` | 3 次 / 15 分钟 |
| `POST /forgot-password` | `forgot` | 5 次 / 15 分钟 |
| `POST /reset-password` | `reset` | 10 次 / 15 分钟 |
| `POST /settings/profile` | `profile_save` | 30 次 / 10 分钟 |
| `POST /topics`、`POST /api/v1/topics` | `topic_create` | 20 次 / 小时 |
| `POST /t/:ident/posts`、`POST /api/v1/topics/:id/posts` | `post_reply` | 60 次 / 10 分钟 |
| `POST /posts/:id/edit` | `post_edit` | 30 次 / 10 分钟 |
| `POST /uploads` | `upload` | 60 次 / 小时 |
| `POST /orders` | `order_create` | 20 次 / 10 分钟 |
| `GET /payments/mock/:out_trade_no` | `mock_pay` | 30 次 / 10 分钟 |

限流是单进程内存实现；多实例部署时如需全局配额，应将桶替换为 Redis。

## 3. 请求体上限

- 配置：`http.max_body_bytes`，环境变量 `GF_MAX_BODY_BYTES`，默认 `33554432`（32 MiB）。
- 通过 `http.MaxBytesReader` 包裹请求体，超限时读取返回错误，上传/表单处理会以 4xx 拒绝。
- 媒体上传仍受 `media.upload.max_size_mb`（默认 20 MB）与用户配额双重限制。

## 4. 指标

配置：

```yaml
http:
  metrics_enabled: true
  metrics_token: "change-me"
```

环境变量：`GF_METRICS_ENABLED`、`GF_METRICS_TOKEN`。

- 未启用时 `/metrics` 不存在（404）。
- 配置 Token 后必须携带 `Authorization: Bearer <token>`，否则 401。
- 输出：
  - `goforum_http_requests_total{method,route,status}`
  - `goforum_http_request_duration_seconds_sum/count`
  - `goforum_db_open_connections`、`goforum_db_in_use_connections`、`goforum_db_wait_count`
  - `goforum_uptime_seconds`、`goforum_build_info{version}`
- 路由标签使用 Gin 的路由模板（如 `/t/:ident`），避免高基数；未匹配路径记为 `unmatched`。
- `/metrics`、`/static/*`、`/uploads/*` 不计入指标。

Prometheus 示例：

```yaml
scrape_configs:
  - job_name: goforum
    authorization:
      credentials: change-me
    static_configs:
      - targets: ["127.0.0.1:8080"]
```

## 5. 健康检查

- `GET /healthz`：进程存活，不访问数据库。
- `GET /readyz`：2 秒超时内 Ping 数据库，返回方言、设置版本、模块数；失败返回 503。
- 建议负载均衡使用 `/readyz`，容器 liveness 使用 `/healthz`。

## 6. 备份与恢复

### 命令

```bash
# 默认输出到 backups/<UTC 时间戳>
./goforum backup

# 指定目录
./goforum backup -o /var/backups/goforum/2026-11-08

# 自定义超时
./goforum backup -o /backup -timeout 1h
```

备份内容：

| 文件 | 说明 |
| --- | --- |
| `database.db` | SQLite `VACUUM INTO` 一致性快照 |
| `database.sql` | MySQL `mysqldump --single-transaction` / PostgreSQL `pg_dump` 纯文本 |
| `uploads.tar.gz` | 本地存储上传目录归档 |
| `manifest.json` | 版本、时间、驱动、文件大小与 SHA256 |

说明：

- SQLite 使用 `VACUUM INTO`，不复制正在写入的 WAL 文件。
- MySQL 通过 `MYSQL_PWD` 传密码，避免出现在进程参数。
- PostgreSQL 使用 `--dbname=<DSN>`；需要 `pg_dump` 与数据库版本匹配。
- S3/对象存储不在本命令范围，应使用桶版本或厂商快照。

### 恢复步骤

1. 停止应用。
2. SQLite：用 `database.db` 替换 `data/goforum.db`，删除残留 `-wal/-shm`；MySQL/PostgreSQL：导入 `database.sql`。
3. 解压 `uploads.tar.gz` 到 `storage.local_path`。
4. 校验 `manifest.json` 中 SHA256。
5. 启动应用，访问 `/readyz`、首页、登录、主题页、`/admin` 做冒烟。
6. 目标恢复时间：小型站点 < 30 分钟，中型站点 < 2 小时。

## 7. 压测

```bash
BASE_URL=http://127.0.0.1:8080 k6 run scripts/loadtest.js
```

默认场景：5 → 30 VU 爬坡，持续约 2 分钟；阈值：

- `http_req_failed < 1%`
- `p95 < 500ms`、`p99 < 1000ms`

建议同时观察 `/metrics` 的 P95 趋势、数据库连接池与错误率，并对搜索、支付回调单独压测。

## 8. 升级修复：subscriptions 表拆分

**问题**：M2 的关注功能与 M5 的 VIP 订阅都使用表名 `subscriptions`。GORM AutoMigrate 将两套字段合并到同一张表，导致：

- 旧库升级时尝试添加 `product_id NOT NULL` 失败；
- 新库中关注写入因缺少 `product_id` 失败；
- 关注与订阅数据混在一起。

**修复**：

- 关注表改为 `follow_subscriptions`，唯一索引改为 `uk_follow_subscription`。
- 订阅表改为 `billing_subscriptions`。
- 启动时执行一次性迁移 `migrateLegacySubscriptions`：
  1. 若旧 `subscriptions` 存在，先按 `target_type` 复制关注行；
  2. 若存在 `product_id` 列，再复制订阅行；
  3. 两者均成功后删除旧表；
  4. 复制使用 `NOT EXISTS`，可重复执行。
- 迁移在事务中执行；失败则启动中止，避免半迁移状态。

## 10. 当前边界

- 限流为单进程内存，多实例需要 Redis 或网关层限流。
- 指标为进程内聚合，重启清零；长期存储依赖 Prometheus。
- 备份命令只覆盖本地存储；S3 需使用桶策略。
- 未提供自动定时备份与保留策略，建议用 cron/systemd timer 调用 `goforum backup`。
- 未生成 pprof 性能剖析入口；压测调优时可按需临时开启。
