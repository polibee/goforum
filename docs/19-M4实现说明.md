## 3. 关键实现

### 3.1 积分账本

- 流水唯一键 `(user_id, rule_code, ref_type, ref_id)`，同一业务事件重复投递不会重复加分。
- 加分/扣分与余额更新在同一事务；扣分使用 `balance >= amount` 条件更新，避免并发透支。
- 每日上限按 `rule_code` 统计当日正向流水。
- 余额变动后按 `levels.min_points` 重新计算等级并写回余额表。
- 事件来源：`post.created`（主题/回复）、`reaction.added`（获赞）；签到、邀请、悬赏走服务调用。

### 3.2 邀请

- 邀请码 16 位十六进制大写，7 天有效；可绑定邮箱。
- 默认配额 3 个“未使用且未过期”的邀请码。
- 注册流程：校验邀请码 → 创建用户 → 消费邀请码 → 邀请人加分（规则 `invite.success`）。
- 邀请制模式下缺少邀请码会被拒绝；开放模式也支持携带邀请码注册。

### 3.3 抽奖

- 开奖前校验状态与截止时间；参与消耗积分，重复参与被拒。
- 开奖使用 `crypto/rand` 生成种子，按种子洗牌选取中奖者；种子与名单写入数据库，便于复核。
- 管理端可手动开奖；开奖操作写审计。

### 3.4 悬赏

- 发布时校验主题作者身份，冻结积分（扣分流水 `bounty.freeze`）。
- 结算时校验回复属于该主题，奖励转给回复作者（`bounty.reward`）。
- 发布者或管理员可退款（`bounty.refund`）。
- 状态机：`pending → funded → settled | refunded`。

## 5. 与设计的差异

| 设计 | 现状 | 计划 |
|---|---|---|
| 悬赏到期自动退款 | 仅手动退款 | 定时任务 |
| 抽奖奖品自动发放 | 仅记录中奖名单 | 与积分/徽章/权益打通 |
| 徽章规则引擎 | 仅首次发帖、连续 30 天 | 后续扩展 |
| 积分过期/回收 | 未实现 | 合规场景再加 |
| 签到时区 | 统一 UTC 日期 | 可按用户时区 |
| 邀请奖励防刷 | 基础配额 | 风控规则 |
| 等级权限联动 | 等级仅展示/抽奖门槛 | M3 信任等级已独立 |

## 6. M5 入口

1. **商业化**：商品、订单、支付渠道、回调、退款、订阅、权益、复式账本、对账。
2. **积分与余额兑换**：积分包、VIP、邀请码包、付费内容。
3. **支付渠道**：余额、人工、支付宝、微信；二期 Stripe/PayPal。
4. **对账任务**：关单、补偿查询、退款重试、每日对账。
