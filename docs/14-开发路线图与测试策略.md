# 14 开发路线图与测试策略

## 1. 交付原则

1. **垂直切片**：每个里程碑都交付“数据 → 服务 → API → 页面 → 后台 → 测试”的完整链路，不做只有后端的半成品。
2. **先内核后玩法**：模块框架、设置、权限、审计先稳定，再叠加运营与商业化。
3. **支付最后做但最早设计**：接口与账本在 M0 定稿，M5 实现，避免返工。
4. **每个里程碑可上线**：P0 范围在 M3 结束即可上线基础社区；M4–M6 为增强。
5. **文档同步**：行为变更必须同时更新 03/04/05/07/08/10 对应章节。

## 2. 里程碑

### M0 平台内核与后台外壳（3–4 人周）

**交付**

- 配置加载与校验（默认值/数据库/环境变量/启动参数）
- 多数据库打开与方言层（SQLite/MySQL/PostgreSQL）
- 迁移框架与空库初始化
- 可插拔接口与默认实现：cache（memory）、storage（local）、events（outbox）、mail（log）、queue（in-process）、search（DB）
- 模块注册、依赖排序、manifest 自检
- 设置框架（类型/校验/权限/审计/版本/导入导出）
- 后台外壳：布局、导航聚合、命令面板、仪表盘空壳
- 安装向导（选库、站点信息、管理员、注册策略）
- 模板渲染器、资源管线（Tailwind + esbuild + manifest）
- 请求中间件：request_id、recover、日志、安全头、会话、CSRF、限流
- CI：lint、单测、构建、迁移检查

**验收**

- 空目录启动到安装完成 ≤ 5 分钟；三种数据库均可初始化。
- 后台可登录、改设置、看到变更审计。
- 关闭任一业务模块应用仍可启动。
- 依赖检查能拦截跨模块内部包引用。

### M1 身份与内容核心（6–8 人周）

**交付**

- auth：注册（开放/邀请/审核）、登录、邮箱验证、找回密码、会话、用户组、信任等级、封禁禁言
- community：板块树、标签、主题、回复、编辑历史、草稿、阅读状态、投票、置顶/精华/锁定/归档
- media：图片/附件上传、缩略图、本地存储
- 页面：首页、板块、标签、主题详情、发帖、编辑、登录/注册/找回、用户主页、基础设置
- 后台：主题、回复、板块、标签、用户、用户组
- 基础 SEO：canonical、Meta、robots、主题/板块的索引规则
- 通知：仅站内基础通知（回复/@）

**验收**

- 发帖→回复→编辑→删除→恢复全链路通过。
- 楼层不重号；私有板块不可见；阅读状态跨设备一致。
- 无 JS 可完成注册、发帖、回复。
- 后台可管理内容与用户，操作有审计。

### M2 互动、通知、私信、搜索、媒体完善（5–6 人周）

**交付**

- engagement：点赞、收藏、关注（主题/板块/标签/用户）
- notification：通知中心、偏好、@提及、聚合、SSE、轮询降级
- messaging：私信列表与会话、已读、屏蔽、举报
- search：三方言全文检索、筛选排序、热词、建议、相似主题、降级
- media：图片变体（WebP/AVIF）、配额、孤儿清理、对象存储适配
- 后台：通知模板、搜索配置、附件管理

**验收**

- 通知 5 秒内到达（在线）；静音后零通知。
- 私信非参与者返回 404。
- 搜索权限零泄露；新增内容 5 秒内可搜。
- 三数据库搜索结果语义一致。

### M3 治理与完整后台（4–5 人周）

**交付**

- moderation：举报、审核队列、领取与处理、版主工具（移动/合并/拆分/隐藏/恢复）、敏感词、处罚、小黑屋、审计
- 后台：概览仪表盘、审核队列、举报详情、审计日志、封禁记录、命令面板
- 权限：完整权限键、用户组权限编辑器、板块覆盖
- 反垃圾：新用户审核、频率限制、自动隐藏阈值

**验收**

- 举报→队列→处理→通知→审计闭环。
- 并发领取只有一个成功；操作不可删除。
- 版主仅能在授权板块内操作。
- 仪表盘卡片可独立失败与重试。

> **M3 结束为 P0 可上线版本**（基础社区）。

### M4 运营玩法（4–5 人周）

**交付**

- gamification：积分规则与账本、签到与连续奖励、等级、徽章、邀请码与配额、抽奖、悬赏托管
- 页面：积分/签到、等级、徽章墙、邀请、抽奖、悬赏
- 后台：积分规则、等级、签到、徽章、邀请、抽奖、悬赏
- 事件联动：发帖/回复/点赞/精华自动积分

**验收**

- 余额 = 流水累计；重复行为不重复加分。
- 邀请码一次性；并发使用只成功一次。
- 悬赏冻结、结算、退款金额守恒。
- 抽奖结果可审计复现。

### M5 商业化与支付（6–8 人周）

**交付**

- billing：商品、订单、支付尝试、渠道注册表、余额/人工/支付宝/微信、回调、退款、订阅、权益、复式账本、优惠券、对账
- 页面：定价、收银台、订单/账单、订阅、付费内容解锁
- 后台：商品、订单详情、退款、渠道配置（schema 表单）、对账、报表
- 安全：验签、金额校验、幂等、风控、审计
- 运维任务：关单、补偿查询、退款重试、订阅到期、对账、账本重算

**验收**

- 沙箱完成下单→支付→回调→权益→退款全链路。
- 重放/并发/金额篡改/迟到支付均正确处理。
- 新增渠道不改核心（用一个假渠道验证）。
- 账本平衡可重算；对账能发现注入差异。

### M6 SEO、站点设计与体验（4–5 人周）

**交付**

- SEO：索引矩阵落地、canonical、Meta/OG、JSON-LD、sitemap 分片、robots、RSS、410、诊断报表
- 站点设计：品牌、主题色、暗色、布局、导航构建器、静态页、公告、邮件品牌
- 前端：响应式、无障碍、快捷键、骨架/空态、性能预算
- 后台：品牌/外观/布局/导航/页面/公告/SEO 设置

**验收**

- 索引矩阵自动化测试全通过；sitemap 仅含公开可索引 URL。
- 后台改品牌/导航/主题色即时生效，无硬编码。
- Lighthouse 性能 ≥ 90、SEO = 100、可访问性 ≥ 90。
- 删除内容 410，且从 sitemap 与搜索移除。

### M7 硬化与发布（3–4 人周）

**交付**

- 压测与调优（首页、主题页、搜索、支付回调）
- 安全审计与修复（越权、注入、上传、支付）
- 备份恢复演练、故障演练
- 监控告警、日志与仪表盘
- 文档补齐（部署、运维、升级、FAQ）
- 发布检查清单与回滚预案

**验收**

- 目标容量下 P95 达标、错误率 < 0.1%。
- 无高危/严重安全漏洞。
- 备份可在 2 小时内恢复并通过冒烟。
- 升级与回滚演练成功。

## 3. 团队与分工建议

| 角色 | 人数 | 职责 |
|---|---|---|
| 后端 | 2 | 平台内核、auth/community、billing |
| 前端 | 1–2 | 模板、Alpine 组件、后台、SEO 渲染 |
| 全栈/运维 | 1 | 部署、监控、支付渠道对接、压测 |
| 产品/设计 | 1 | 功能优先级、交互、文案、验收 |

可并行：M2 的搜索与私信、M4 的运营与 M5 的商品可交叉；支付渠道对接依赖商户资质，应尽早启动申请。

## 4. 测试策略

### 4.1 金字塔

| 层 | 占比 | 范围 |
|---|---|---|
| 单元 | ~70% | Service 规则、状态机、校验、清洗、账本、权限策略 |
| 集成 | ~20% | Repository（三方言）、HTTP Handler、SSE、迁移、回调、事件 |
| 端到端 | ~10% | 关键用户旅程（见 4.4） |

### 4.2 单元测试重点

- 订单/退款/订阅/抽奖/悬赏状态机：所有合法迁移与非法迁移。
- 账本：借贷平衡、余额非负、幂等键、重算。
- 权限：组 × 信任等级 × 板块 × 所有权矩阵。
- Markdown 清洗：XSS 载荷、危险协议、SVG、iframe。
- 限流与幂等：重复请求、并发请求。
- 金额与优惠：边界、取整、部分退款。

### 4.3 集成测试重点

- 三方言迁移从空库到最新、重复执行安全。
- Repository 契约测试（同一套用例跑 SQLite/MySQL/PG）。
- 路由与权限：未登录/无权限/私有资源返回码。
- SSE：连接、事件、断线重连、Last-Event-ID。
- 回调：验签、重放、金额不符、并发。
- 事件 outbox：事务提交后投递、失败重试、死信。

### 4.4 端到端旅程

1. 注册 → 验证邮箱 → 登录 → 发主题 → 回复 → 收到通知。
2. 举报 → 审核队列 → 处理 → 作者收到通知 → 审计可见。
3. 购买积分包 → 收银台 → 沙箱支付 → 积分到账 → 消费 → 退款。
4. 后台改站点名/主题色/导航 → 前台即时生效。
5. 删除主题 → 410 → sitemap/搜索移除。
6. 私有板块：无权限用户在所有入口均不可见。

### 4.5 多数据库矩阵

| 数据库 | 每次 PR | 每日 | 发布前 |
|---|---|---|---|
| SQLite | ✅ 单测 + 集成 | ✅ | ✅ |
| MySQL | — | ✅ 容器 | ✅ 全量 |
| PostgreSQL | — | ✅ 容器 | ✅ 全量 |

- 使用 testcontainers 启动真实数据库，不用 mock。
- 方言差异用同一套契约测试断言。
- FTS 单独测试中文分词与排序。

### 4.6 专项测试

| 类型 | 内容 |
|---|---|
| 安全 | 越权矩阵、XSS/SQLi/CSRF、上传绕过、SSRF、支付伪造、限流 |
| 性能 | k6/Locust：首页、主题页、搜索、发帖、回调；目标见 01 |
| 可访问性 | axe 扫描关键页；键盘走查；对比度 |
| SEO | 索引矩阵断言、canonical、JSON-LD 校验、sitemap 内容、410 |
| 兼容性 | Chrome/Safari/Firefox/Edge 最新两个版本；iOS/Android |
| 邮件 | 模板渲染、链接、退信/投诉处理 |
| 备份 | 恢复演练、校验和、RTO 记录 |

### 4.7 测试数据

- 固定种子数据：用户（各 TL）、板块（公开/私有/只读）、主题（各状态）、商品、订单（各状态）。
- 禁止使用生产数据；脱敏工具用于排查。
- 时间相关逻辑使用可注入时钟，避免 sleep。

## 5. CI/CD

```
PR:
  lint → unit → integration(sqlite) → build assets → template smoke
      → govulncheck → docker build → e2e(smoke)

main:
  上述 + integration(mysql/pg) + 安全扫描 + 镜像推送

release:
  全量多库 + 性能基线 + 备份恢复演练 + 变更说明
```

强制门禁：

- 单测覆盖率 ≥ 70%（核心模块 ≥ 80%）。
- 迁移可重复执行。
- 权限键、设置键无重复。
- 无高危依赖漏洞。
- 模板渲染与 SEO 断言通过。

## 7. 风险登记

| 风险 | 影响 | 概率 | 应对 |
|---|---|---|---|
| 三方言行为差异 | 高 | 中 | 方言层隔离 + 契约测试 + 每日多库 CI |
| 中文分词效果差 | 中 | 高 | 预分词 + 同义词 + 可切换外部搜索 |
| 支付资质/渠道审核延迟 | 高 | 中 | 尽早申请；先上余额/人工；渠道插件化 |
| 范围蔓延 | 高 | 高 | P0/P1/P2 严格分级；P1/P2 默认开关关闭 |
| 大表性能 | 中 | 中 | 索引评审 + 压测 + 归档/分片预案 |
| 迁移出错 | 高 | 低 | 备份 + 只加不删 + 回滚演练 |
| 审核人力不足 | 中 | 中 | 自动化规则 + 举报阈值 + 队列优先级 |
| 安全漏洞 | 高 | 中 | ASVS L2 + 安全测试 + 依赖扫描 |
| 邮件送达率 | 中 | 中 | SPF/DKIM/DMARC + 退信处理 + 可关闭邮件 |

## 8. 完成定义（DoD）

一个功能完成必须满足：

- [ ] 代码实现并通过 lint/单测/集成测试
- [ ] 权限键已注册，前端显隐 + 服务端校验一致
- [ ] 写操作有审计（如适用）
- [ ] 迁移可重复执行，索引已评审
- [ ] 页面具备加载/空/错误态，移动端可用
