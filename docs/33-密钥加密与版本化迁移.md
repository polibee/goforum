# 密钥加密与版本化迁移

> 两项生产加固：敏感设置不再明文落库；数据库结构变更改为有版本台账的迁移。

## 1. 设置中的密钥加密

### 范围

所有 `Secret` 类型设置，包括：

- SMTP 密码、Resend API Key
- NOWPayments、Deipay、Creem、Lemon Squeezy 密钥
- Google / GitHub OAuth Client Secret
- 其他声明为 `TypeSecret` 的设置

### 存储格式

- 使用 `APP_KEY`（`GF_SECRET_KEY`）派生 AES-256-GCM 密钥。
- 每条密文独立随机 nonce，格式为 `v1:<base64(nonce+ciphertext)>`。
- `settings.value_json` 中保存的是 JSON 字符串密文，不包含明文。
- 读取时由 `settings.Store` 透明解密，调用方（邮件、支付、OAuth）无需改动。

### 兼容已有数据

- 旧版本已存在的明文密钥仍可正常读取。
- 应用启动时 `SetSecretKey` 会扫描所有已配置的 Secret 设置，就地加密并更新数据库，无需管理员重新填写。
- 迁移失败只记录警告，不阻断启动；下次启动会重试。
- 新写入 Secret 设置时如果 `APP_KEY` 为空，保存会被拒绝并提示配置 `APP_KEY`，不会退回明文。

### 密钥轮换

- 更换 `APP_KEY` 后，旧密文无法解密。
- 管理后台「站点设置」会显示无法解密的设置项名称，提示重新填写。
- 已加密的 TOTP 密钥同样依赖 `APP_KEY`；轮换前应先处理 2FA。
- 备份文件使用独立的 `GF_BACKUP_KEY`，与设置加密互不影响。

## 2. 版本化迁移

### 台账

新增 `schema_migrations` 表：

| 字段 | 说明 |
|---|---|
| `version` | 递增版本号，主键 |
| `name` | 迁移名称 |
| `applied_at` | 应用时间 |

已注册迁移：

| 版本 | 名称 | 内容 |
|---|---|---|
| 1 | `baseline_models` | 按当前模型集合建立基线（GORM AutoMigrate，幂等） |
| 2 | `legacy_subscriptions` | 拆分旧 `subscriptions` 数据 |

### 命令与启动校验

- `./goforum migrate`：按版本顺序执行未应用迁移，成功后输出 `database schema is up to date`。
- 安装向导在空库上调用 `MigrateFresh`，先执行版本化迁移再创建管理员。
- 生产模式启动：
  1. `EnsureSchema` 校验表和列；
  2. `EnsureMigrationsApplied` 校验台账是否缺失或落后；
  3. 任一失败都返回 `ErrSchemaIncomplete` 并退出，提示执行 `goforum migrate`。
- 开发模式仍使用 AutoMigrate 方便迭代，不写入台账；切换生产前执行一次 `goforum migrate` 即可补齐。

### 新增迁移的约定

1. 在 `internal/app/schema.go` 的 `schemaMigrations` 末尾追加新版本，版本号必须递增。
2. 不要修改已经发布过的迁移；修改会导致已升级实例不会重跑。
3. **后续迁移必须幂等**：基线使用当前模型集合，全新安装时基线已经创建了最新表/列；新增迁移应先 `HasTable` / `HasColumn` 判断，或使用 `AutoMigrate` 的幂等语义，避免在全新库上重复加列失败。
4. 需要方言差异时，在 `Up` 中根据 `tx.Dialector.Name()` 分支执行 SQL。
5. 数据迁移也必须可重复执行；DDL 在 MySQL 上可能隐式提交，失败后可用 `goforum migrate` 重试。
6. 生产升级前先 `goforum backup`；多实例环境由单个实例执行迁移（当前未实现 advisory lock）。

## 3. 测试

- `internal/platform/secretbox/secretbox_test.go`：AES-GCM 往返、错误密钥、缺失密钥、base64 密钥。
- `internal/platform/settings/settings_test.go`：
  - Secret 落库为 `v1:` 密文且不含明文；
  - 读取透明解密、UI 掩码、修订记录为 `***`；
  - 旧明文密钥启动时自动迁移；
  - 无 `APP_KEY` 时拒绝写入；
  - 错误密钥产生 `SecretErrors`。
- `internal/platform/db/migrate_test.go`：版本记录、幂等执行、台账缺失/落后、失败不记录、非法迁移定义。
- `internal/app/schema_test.go`：基线+存量迁移记录、缺失台账时生产启动拒绝。
- 计费测试使用测试密钥，验证支付密钥经加密后仍可被网关读取。

`go vet ./...` 与 `go test ./...` 全部通过；预览、PostgreSQL、MySQL 三个实例均已执行 `goforum migrate` 并正常启动。

## 4. 注意事项

- 备份仍然包含加密后的设置密文；恢复时必须保留对应 `APP_KEY`。
- `goforum migrate` 不自动备份，生产升级流程需先备份。
- `schema_migrations` 只校验版本是否存在，不校验迁移内容哈希；不要改写已应用迁移。
- 多实例同时执行迁移目前没有数据库锁，需由部署脚本保证串行。
