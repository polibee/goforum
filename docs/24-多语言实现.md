# 多语言（i18n）实现说明

本站采用「源文案作为 key + 按功能拆分翻译文件」的方案：中文模板原文保持不变，渲染时按当前语言查表替换；未翻译的条目自动回退中文。

## 1. 支持语言与切换

| 语言 | 代码 | 说明 |
| --- | --- | --- |
| 简体中文 | `zh-CN` | 源语言，无需翻译文件 |
| English | `en-US` | 提供前台英文翻译 |

语言解析优先级：

1. URL 查询参数 `?lang=en-US`
2. Cookie `gf_lang`（有效期 1 年）
3. 登录用户在「个人资料 → 界面语言」中的选择（存 `users.locale`）
4. 浏览器 `Accept-Language`（仅未登录用户）
5. 站点默认语言 `site.general.locale`
6. 最终回退 `zh-CN`

登录用户明确选择「跟随站点默认」时，跳过 `Accept-Language`，直接使用站点默认语言。

页头右侧提供语言菜单（中文 / English）。切换后写入 Cookie，后续请求自动沿用；`?lang=` 也会同步写入 Cookie。登录用户还可以在「个人资料」中保存长期语言偏好，保存时同步写入 Cookie。

响应会设置 `Content-Language`，`<html lang>` 使用当前语言。

## 2. 目录结构

```
web/locales/
├── en-US/
│   ├── common.json       # 全局导航、通用按钮、通用错误
│   ├── auth.json         # 登录/注册/找回密码/安装/资料
│   ├── community.json    # 首页、板块、主题、发帖、编辑、用户
│   ├── billing.json      # 定价、收银台、订单、订阅
│   ├── gamification.json # 积分、签到、邀请、抽奖、悬赏
│   ├── notify.json       # 通知、私信
│   ├── moderation.json   # 举报
│   └── admin.json        # 后台导航、表单与页面标题
└── zh-CN/                # 预留；源语言不需要 catalog
```

文件按功能（模块）拆分，加载时合并为该语言的单一查找表。键是中文源文案，值是对应语言译文：

```json
{
  "登录": "Log in",
  "忘记密码？": "Forgot password?"
}
```

## 3. 运行时

### 加载

- `internal/platform/i18n` 从嵌入的 `web/locales` 读取所有语言目录与 `*.json`。
- `zh-CN` 始终视为支持，未提供文件时使用源文案。
- 启动时校验 JSON，格式错误会阻止启动。

### 模板函数

模板中使用：

```html
<h1>{{t "登录" $.Lang}}</h1>
<button>{{t "保存" $.Lang}}</button>
```

- 第一个参数是中文源文案；第二个参数是当前语言 `$.Lang`。
- 未找到译文时原样返回中文，保证缺翻译不会出现空白。
- 自动转义仍由 `html/template` 负责。

### 自动标注

`scripts/i18n-wrap.py` 会扫描模板中的静态中文文本节点，以及 `placeholder`、`title`、`aria-label`、`alt`、`value` 属性，自动包裹为 `{{t "..." $.Lang}}`：

```bash
python scripts/i18n-wrap.py          # 预览
python scripts/i18n-wrap.py --write  # 写入
```

包含模板动作的混合文本（如 `{{.Count}} 条`）不会被整体包裹，避免破坏变量；这类文案可手动拆分后翻译。

## 4. 已覆盖范围

- 全局页头、页脚、语言菜单、主题切换、导航
- 登录、注册、找回密码、安装向导、个人资料
- 首页/板块/标签/主题列表、主题详情、发帖、编辑、用户主页
- 定价、收银台、订单、订阅
- 积分、签到、邀请、抽奖、悬赏
- 通知、通知设置、私信、会话
- 举报
- 通用错误与 flash 消息（通过 `{{t .Message $.Lang}}`）

英文目录当前包含约 370 条译文，覆盖全部前台静态文案与通用错误/提示。

后台管理页面已完成模板标注，并提供 `web/locales/en-US/admin.json`。`/admin?lang=en-US` 可显示英文后台；页面标题通过 `tTitle` 翻译标题主体并保留站点名后缀。静态页标题等内容数据不翻译。

## 5. SEO

- 非默认语言的 canonical 追加 `lang` 参数。
- 页面输出 `hreflang`：
  - `zh-CN`：当前地址 + `lang=zh-CN`
  - `en-US`：当前地址 + `lang=en-US`
- `?lang=` 只影响 UI 语言，不改变内容本身；用户生成内容（主题、回复、私信）不会被翻译。

## 6. 测试与冒烟

单元测试：

- 合并多个功能文件后的查找
- 未知键回退中文
- `zh-CN` 直接返回源文案
- `?lang`、`Accept-Language`、默认语言解析
- Cookie 写入

冒烟：

- `/?lang=en-US` 输出 `lang="en-US"`，页头显示 Home / Search / Top up / Log in
- 登录页显示 Log in / Password / Forgot password?
- 切换 `?lang=zh-CN` 后恢复中文
- 仅带 Cookie 访问时保持英文

## 7. 预览中修复的问题

- **主题/话题词义冲突**：`主题` 同时用于“讨论主题”和“主题外观”。主题切换按钮改用独立键 `主题外观`，英文为 `Theme`。
- **后台语言混排**：`/admin` 强制 `zh-CN`，避免未翻译的后台与英文通用词混排。
- **移动端导航**：新增 `md:hidden` 菜单，包含首页、搜索、充值、发布、收藏、私信、订单、资料与主题切换；语言切换在移动端保持可见。
- **静态资源缓存**：`asset` 模板函数追加内容哈希 `?v=<hash>`；静态资源仍使用一年 immutable 缓存，但发布新构建后 URL 自动变化，避免浏览器继续使用旧 CSS/JS。
- **页脚吸底**：页面改为 flex 纵向布局，短内容页面页脚固定在视口底部。

## 8. 扩展新语言

1. 新建 `web/locales/ja-JP/`，按功能添加 JSON 文件。
2. 在 `i18n.Bundle.resolve` 的 Accept-Language 分支增加语言前缀映射（如 `ja` → `ja-JP`）。
3. 页头语言菜单增加链接。
4. 运行模板扫描确认没有新增未包裹文案。

## 9. 当前边界

- 后台英文依赖 `admin.json`，新增后台文案需同步补充。
- 处理器中动态拼接的文案（含变量）如未进入 catalog，会回退中文；建议后续改为格式化键或拆分模板。
- 用户生成内容不翻译。
- 翻译键使用中文源文案，修改中文文案会导致对应英文失配；修改时需同步更新 catalog。
- 未接入翻译管理后台；翻译文件随代码发布。
