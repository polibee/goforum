## 2. 认证与 OAuth

- `OAuthState` 现在包含 PKCE `code_verifier`，Cookie 使用 `APP_KEY` 做 HMAC-SHA256 签名；回调校验签名、provider 与 `state` nonce（常量时间比较）。
- 授权 URL 使用 `S256` PKCE；token 交换携带 `code_verifier`。
- OAuth state Cookie 的 `Secure` 标志同时识别 TLS 与 `APP_URL=https://`。
- `oauth.auto_link_email` 默认改为 `false`。关闭时若邮箱已存在，拒绝创建重复账号并提示先登录后绑定，不再静默合并。
- 登录密码与 TOTP 挑战增加账号维度失败计数：5 次失败锁定 15 分钟，使用共享缓存（Redis 时跨实例）；锁定事件写审计日志。
- `APP_ENV` 为空不再视为开发环境；仅 `development`/`dev`/`test` 跳过 TOTP 强制与启用 AutoMigrate。

## 3. 广告与内容安全

- `/ads/:id/frame` 响应增加 CSP `sandbox allow-scripts allow-popups`（不含 `allow-same-origin`），iframe 同时设置 `sandbox` 与 `no-referrer`。
- HTML 广告只能由超级管理员创建或编辑；自助推广仍只允许文字/图片。
- 广告 iframe 与父页面隔离为不透明源，无法读取父 DOM、Cookie 或 CSRF Token。

## 4. 支付与资金

- 退款改为 `paid -> refunding -> refunded` CAS 状态机；并发退款只有一个请求能调用渠道。
- 退款顺序：CAS 锁定 → 扣回积分 → 调用渠道 → 本地账本/权益；积分扣回失败或渠道失败会回滚订单与积分。
- 外部渠道退款只冲销 `clearing`，不再向用户站内余额入账；只有 `balance` 渠道退款回到站内余额。
- 渠道回调写入 `payment_notify_logs`（原始报文、验签、处理结果、错误），重复事件按 `(channel, event_id)` 幂等。
- 回调要求金额与币种匹配（渠道能提供时）：NOWPayments 使用订单币种与精确十进制金额；Creem/Lemon/Deipay 标记 `AmountVerified`；XCash 回调无金额字段，仍依赖签名与订单号。
- 已支付订单的重复回调直接返回，不再重复发积分或 `order.paid` 事件。
- 网关下单失败会释放优惠券占用；关闭订单复用同一释放逻辑。
- 生产环境新建站点默认禁用支付宝/微信沙箱渠道；模拟支付改为 POST 表单并提交 CSRF Token。

## 5. 上传、搜索与迁移

- 图片总像素上限 2500 万；JPEG/PNG/GIF 解码后重新编码，WebP 重写 RIFF 容器移除 EXIF/XMP 并清理 VP8X 标志。
- 上传大小、配额与哈希基于处理后的文件。
- 搜索表与 FTS/GIN 索引进入版本化迁移 `0003 search_schema`；生产启动只做 `DetectSchema`，不再执行 AutoMigrate/DDL。
- **升级注意**：已有部署必须先执行 `./goforum migrate`，否则启动会因缺少 `0003` 拒绝启动。

## 6. 仍未实现

| 项 | 原因 / 建议 |
|---|---|
| 事务 Outbox 与死信队列 | 需要新增 `event_outbox`/`failed_jobs` 表与后台 worker；当前事件总线仍是同步投递，失败记录日志。 |
| secretbox AAD | 已支持 `APP_KEY_PREVIOUS` 轮换回退与自动重写；密文仍未绑定 AAD（如 setting key/user id），数据库行间替换防护有限。 |
| 迁移 advisory lock / checksum | 多实例同时执行 `goforum migrate` 仍需人工串行。 |
| S3/对象存储 | 上传仍为本地磁盘，多实例需共享卷。 |
| 支付宝/微信生产签名 | 仍为沙箱渠道，生产需接入正式证书与签名。 |
